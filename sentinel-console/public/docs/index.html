架构概览

这不是一个对话产品。Sentinel 是一个以「可量化可靠性」为主题的 Agent 引擎：把 LLM tool-calling 循环工程化——模型提议，代码裁决；效果用同一题库对三种编排形态的机械评测来量化，而不是靠演示印象。

核心主张 三个可量化的能力 产品载体 业务模块 整体架构 双通道链路

核心主张：模型提议，代码裁决

模型负责（提议）

语义判断

场景与意图分流（embedding 快路径）；在装载集内选择工具与参数；解读与表达。

代码强制（裁决）

确定性边界

裁剪模型可见的工具集（scoped | search）；G1–G7 治理中间件是唯一执行咽喉；预算与只读红线；输出数字接地与结果块投影。

不接受概率裁决：权限、预算、红线这类不可挽回的决策全部由查表和中间件确定执行，不交给模型判断；交易类工具物理上不在工具目录中（红线物理化）。

证据方式：全部指标由代码断言产生，无 LLM 判官；对照基线是裸 tool calling 与 LangGraph 官方 ReAct——同一题库、同一模型、同一份数据，见 三种架构对照。

产品载体：主动式持仓看护 Agent

引擎的第一个应用是 watch-first 的持仓看护：事件驱动主动解读，推送带证据链与审计码的结构化通知；分析能力以固定分析用例提供（预设台词、单次运行、真实循环）。只读红线：不做交易、不出具投资适当性结论；不提供自由对话入口。

事件源（价格阈值 / 晨报 / 演示注入） → WatchEvent（幂等落库） → 唤醒组装（持仓 + 画像 + 目标记忆） → Agent 引擎（装载 + G1–G7 裁决） → 结构化通知（证据 / 审计码 / 严重度） 固定分析用例 → 快路径或循环 → SSE 流式 + ResultBlock

业务模块

FRONTEND

sentinel-console

文档站 /（即本页）。看护与分析用例演示页不进入公开导航。浏览器只访问同源 /api/。

ENGINE

sentinel-engine

看护环（事件源 / 唤醒 / 通知）与固定分析用例（Agent 循环 / SSE）；统一工具目录与治理中间件。

DATA

sentinel-data

认证、持仓与画像、运行索引、任务与 Registry；引擎不直连业务库。

MEMORY

sentinel-memory

L3 语义记忆（Remote Memory Service）；召回失败视为空结果，不阻塞应答。

整体架构

单一执行引擎，双通道驱动：差异仅在输入契约（WatchEvent vs 预设用例）、上下文组装与输出形态（结构化通知 vs 流式分析响应）。

Console (Nginx / dev-server) → Python Engine（watch / AgentLoop / governance） → ToolCard 本地工具 + MCP → Observation → ResultBlock / 通知 → SSE / REST ← Java Data Plane（JWT / 持仓 / 运行投影） ← Memory Service（L3 recall）

双通道链路

看护环（事件驱动）

WatchEvent（价格阈值 / 晨报 / demo_inject） → 幂等落库（dedupe_key） → 唤醒组装器 + scene_wakeup → Agent 解读 → 通知落库（证据 / 审计码 / 演示水印） → SSE notification → 时间线

分析用例（用户点选）

预设用例台词 → 语义快路径或 Agent 循环 → bind_tools + 治理中间件 → token / tool.step / response.final → ResultBlock + 证据链上屏
无对话入口：会话式流式管线保留为引擎内部能力（分析用例运行复用），前端不提供自由对话页面。
