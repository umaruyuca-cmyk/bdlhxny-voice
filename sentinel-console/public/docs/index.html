架构概览

Sentinel 是主动式持仓看护 Agent：事件驱动主动触达，对话作为追问与自由交互通道。两通道共用同一执行引擎与治理中间件。

业务模块

FRONTEND

sentinel-console

品牌落地 /、看护 /dashboard、会话 /agent。浏览器只访问同源 /api/。

ENGINE

sentinel-engine

看护环（事件源 / 唤醒 / 通知）与会话环（Agent 循环 / SSE）；统一工具目录与治理中间件。

DATA

sentinel-data

认证、持仓与画像、会话/运行索引、任务与 Registry；引擎不直连业务库。

MEMORY

sentinel-memory

L3 语义记忆（Remote Memory Service）；召回失败视为空结果，不阻塞应答。

整体架构

单一执行引擎，双通道驱动：差异仅在输入契约（WatchEvent vs 用户消息）、上下文组装与输出形态（通知 vs 流式会话）。

Console (Nginx / dev-server) → Python Engine（watch / AgentLoop / governance） → ToolCard 本地工具 + MCP → Observation → ResultBlock / 通知 → SSE / REST ← Java Data Plane（JWT / 持仓 / 会话投影） ← Memory Service（L3 recall）

双通道链路

看护环（事件驱动）

WatchEvent（价格阈值 / 晨报 / demo_inject） → 幂等落库（dedupe_key） → 唤醒组装器 + scene_wakeup → Agent 解读 → 通知落库（证据 / 审计码 / 演示水印） → SSE notification → P1 时间线

会话环（用户发起）

用户消息 / 追问 followup → 语义快路径或 Agent 循环 → bind_tools + 治理中间件 → token / tool.step / response.final → ResultBlock + 证据链上屏
