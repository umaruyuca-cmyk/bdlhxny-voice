# StockWise 全新股票分析系统

## 代码质量问题与修改方案

> 版本：v1.0  
> 状态：待实施  
> 更新时间：2026-08-06  
> 适用范围：`stockwise-analysis` Python LangGraph + Mem0 主版本  
> 依据文档：`docs/prompts/23-全新股票分析系统-统一开发实施Prompt.md`

---

## 1. 审查结论

当前代码已经具备较完整的基础结构：

- LangGraph Root Graph、Query Graph 和 Market Data Graph 已建立；
- `AnalysisInput` / `AnalysisResult` / `Observation` 等结构化契约已建立；
- Mem0、MCP、Java Data API 和 Analysis Engine 已预留适配边界；
- Python、Node、前端和 Java 基础测试均可以运行。

但是，当前测试主要覆盖 Mock 路径，真实 MCP 路径尚未达到可运行质量。最严重的问题是 Market Data Graph 的 ReAct 内部状态没有声明在 LangGraph State 中，导致真实 Gateway 路径会反复执行并最终触发 `GraphRecursionError`。

因此当前结论为：

> 基础骨架可用，Mock 流程可用，真实 MCP 端到端流程不可用，暂不具备生产运行条件。

## 2. 问题等级定义

| 等级 | 含义 | 处理要求 |
|---|---|---|
| P0 | 阻断主流程或可能导致无限循环、错误数据进入分析 | 修改前不得接入真实 MCP 或部署生产 |
| P1 | 违反核心架构约束，导致关键能力不可用或产生错误结论 | 第一轮修复必须完成 |
| P2 | 质量、可观测性、维护性或文档一致性问题 | 主流程稳定后完成 |

## 3. P0 阻断问题

### 3.1 ReAct 内部状态没有进入 RootState

涉及文件：

- `stockwise-analysis/src/stockwise_analysis/runtimes/langgraph/graphs/state.py`
- `stockwise-analysis/src/stockwise_analysis/runtimes/langgraph/graphs/market_data_graph.py`

当前 `market_data_graph.py` 使用以下内部字段：

```text
_current_action
_pending_observation
_react_round
```

但这些字段没有声明在 `RootState` 中。LangGraph 节点返回的未知字段不会按照预期在后续节点间可靠传递，导致：

1. `select_action` 生成的动作丢失；
2. `execute_tool` 读取到空动作；
3. `_pending_observation` 无法传给 `normalize_observation`；
4. ReAct 轮次始终无法递增；
5. 子图无限循环，最终触发 `GraphRecursionError`。

修复要求：

- 将内部状态字段加入 `RootState`，并明确字段类型；或为 Market Data Graph 定义专用 `MarketDataState`；
- 标量字段不得使用错误的 list reducer；
- `observations`、`events` 等追加字段继续使用明确 reducer；
- 增加注入 Fake Gateway 的真实 ReAct 回归测试；
- 测试必须验证 action、pending observation 和 round counter 在节点间正确传递；
- 测试必须验证最终能够进入 `evaluate_market_data`，不能只验证不抛异常。

验收标准：

```text
Fake Gateway 注入
→ select_action
→ execute_tool
→ normalize_observation
→ evaluate_market_data
→ 子图结束
```

不得出现 `GraphRecursionError`。

## 4. P1 主流程问题

### 4.1 MCP 正常响应没有解析为业务数据

涉及文件：

- `integrations/mcp/adapter.py`
- `observations/normalizer.py`
- `runtimes/langgraph/nodes/nodes.py`

当前 Adapter 将响应包装为：

```json
{
  "raw_text": "...",
  "source_used": "..."
}
```

Normalizer 只识别 `error=true`，没有将正常 JSON 转换为统一的业务结构。因此真实 MCP 成功后，分析层仍然无法得到：

- 实时行情对象；
- 历史 K 线列表；
- 财务报表；
- 估值数据；
- 行业、资金流和新闻数据。

修改要求：

- MCP 原始返回必须在 Normalizer 中解析；
- 根据 capability 执行字段映射、单位转换和格式校验；
- 正常响应转换为 `Observation.data` 业务结构；
- 原始响应只保留为受控的 `raw_reference` 或审计引用，不得直接进入 `AnalysisInput`；
- 解析失败必须返回 `FAILED` 或 `UNAVAILABLE`，不能包装成成功；
- 增加 quote、historical prices、financial statements 的 fixture 测试。

### 4.2 MCP fallback 没有覆盖协议错误和服务端吞错

涉及文件：

- `integrations/mcp/adapter.py`
- `observations/normalizer.py`
- `runtimes/langgraph/graphs/market_data_graph.py`

当前只有网络异常会触发 fallback。以下两类错误不会触发备用源：

- MCP 协议层 `isError=true`；
- MCP 返回 `isError=false`，但响应体为 `{"error": true}`。

修改要求：

- Adapter 必须把协议错误视为一次失败尝试；
- Normalizer 识别服务端吞错后，必须将结果反馈给路由层；
- 主源失败后最多切换一次异构 source；
- 事件流必须记录 `fallback_triggered`；
- 主备均失败时写入 `known_unavailable`，返回 `PARTIAL` 或 `LIMITED`；
- 不得调用 Skill 或 stock-wrapper 作为隐藏备份源。

### 4.3 生产 Checkpointer 没有真正接入

涉及文件：

- `runtime/application.py`
- `runtimes/langgraph/graphs/root_graph.py`
- `api/routes.py`

当前只禁止 production 使用 `memory` 配置，但即使设置 `postgres` 或 `redis`，Root Graph 仍然默认编译为 `InMemorySaver`。

同时，API 使用进程内 `InMemoryRunStore` 保存运行快照，服务重启或多实例部署后无法通过同一 `thread_id` 恢复。

修改要求：

- 增加 Checkpointer Factory；
- 根据配置创建 PostgreSQL 或 Redis Checkpointer；
- `create_application()` 必须把持久化 Checkpointer 注入 `build_root_graph()`；
- production 环境禁止未注入 Checkpointer 启动；
- API 的查询和恢复应以 Checkpointer 状态为准，不以进程内字典作为事实来源；
- 增加“中断 → 服务重启 → 同一 thread_id resume”的集成测试。

### 4.4 ContextBuilder 没有接入真实流程

涉及文件：

- `runtimes/langgraph/context/context_builder.py`
- `runtimes/langgraph/agents/query_agent.py`
- `runtimes/langgraph/agents/summary_model.py`
- `runtime/application.py`
- `runtimes/langgraph/graphs/root_graph.py`

当前 ContextBuilder 只有独立单元测试，没有被 Root Graph 或 Agent 调用。Mem0 读取的 `user_profile` 和 `recalled_memories` 没有组装为模型上下文。

修改要求：

- Application Runtime 创建并注入 ContextBuilder；
- Query Agent 使用七块上下文中的必要块；
- Summary Model 使用 `round_data`、`AnalysisResult` 和限制信息；
- ReAct Agent 只能看到受控工具清单和当前轮 Observation；
- Mem0 召回内容只能出现在上下文的语义记忆块；
- ReAct 循环内不得读写 Mem0。

### 4.5 ReAct 执行矩阵和预算没有接线

涉及文件：

- `runtime/budgets.py`
- `runtime/application.py`
- `runtimes/langgraph/graphs/market_data_graph.py`
- `runtimes/langgraph/agents/research_agent.py`

当前问题：

- Research Agent 被固定创建为 `analysis_type=""`；
- comprehensive 不会真正启用 `LlmResearchAgent`；
- `market_snapshot` 仍然进入 ReAct，而 Prompt 要求走确定性快路径；
- 所有类型使用固定的 6 轮上限；
- `ANALYSIS_BUDGETS` 没有参与 Graph 调度、Tool 次数和超时控制。

修改要求：

- Query Agent 产出 `analysis_type` 后，再创建或选择对应的 Research Agent；
- `market_snapshot` 禁用 ReAct；
- technical、fundamental、valuation 只在字段缺失或主源失败时有限自适应；
- portfolio impact 使用受限 ReAct；
- comprehensive 使用完整但有界的 ReAct；
- 每次 Tool、LLM、Java API 调用都必须受预算约束；
- 超出预算返回 `LIMITED`，不得继续调用。

### 4.6 标的解析仍使用 Mock，没有调用统一 Gateway

涉及文件：

- `runtimes/langgraph/nodes/nodes.py`
- `integrations/mcp/routing_policy.py`

当前 `resolve_instrument()` 直接生成 Mock `InstrumentRef`，没有调用 `market.resolve_instrument`。这会导致 MCP 路由表中的标的解析能力永远不会执行。

修改要求：

- 标的解析也必须经由 MarketDataGateway；
- 返回结果先进入 Observation Normalizer；
- 解析失败时触发补充信息 interrupt 或返回结构化 LIMITED；
- 不允许在节点中拼接“标的名称”。

### 4.7 分析输入没有装配完整数据域

涉及文件：

- `runtimes/langgraph/nodes/nodes.py`
- `contracts/analysis.py`

当前 `assemble_analysis()` 只装配行情、历史价格和持仓，没有装配：

```text
financial_data
valuation_data
industry_context
news_context
overseas_context
```

因此 fundamental、valuation、comprehensive 即使完成查询，Analysis Engine 也无法使用。

修改要求：

- 按 capability 将 Observation 映射到 AnalysisInput 对应字段；
- 对每个字段保留质量状态、来源和时间信息；
- 缺失字段必须进入 limitations 和 `known_unavailable`；
- 增加综合分析完整输入 fixture 测试。

## 5. P1 依赖和外部服务问题

### 5.1 Python 依赖清单遗漏 MCP SDK

`pyproject.toml` 当前没有声明 `mcp`，但 MCP Client 在运行时会导入：

```python
from mcp.client.session import ClientSession
from mcp.client.sse import sse_client
from mcp.client.streamable_http import streamable_http_client
```

在干净环境中安装项目依赖后，真实 MCP 调用会因 `ImportError` 自动进入失败/降级路径。

修改要求：

- 将 MCP SDK 加入正式依赖或明确的生产 extra；
- 在 CI 中执行一次真实 Client 构造测试；
- 分别覆盖 SSE 和 Streamable HTTP 两种传输。

### 5.2 交易日历没有实际实现

`domain/trading_calendar.py` 当前只有 `TradingCalendarProvider` Protocol，没有 A 股交易日历实现，也没有 `exchange-calendars` 依赖。

修改要求：

- 增加本地交易日历实现；
- 覆盖节假日、调休补班和特殊交易日；
- 交易日历不能作为 MCP Tool；
- 增加至少一组 2026 年节假日回归 fixture。

### 5.3 Java Data API 路径和真实后端不匹配

当前 Python Adapter 使用：

```text
/api/portfolio.get_current_positions
```

现有 Java 后端没有对应的 Controller 路由，也没有看到持仓、账户、风险画像对应的 Python Adapter API 契约。

修改要求：

- 与 Java 后端共同确定正式 API 路径、请求参数、认证方式和响应契约；
- Adapter 不得自行拼接 capability 作为 URL；
- 增加 Java API Contract Test；
- 支持用户身份凭证传递；
- 配置了 Java 地址后，404、401、超时不得静默返回模拟持仓；
- 生产环境只能返回真实数据、`UNAVAILABLE` 或 `LIMITED`。

## 6. P2 质量问题

### 6.1 Observation 溯源字段不完整

Prompt 要求记录：

- MCP 名称；
- 统一能力名称；
- 原始工具名；
- 请求参数和 source；
- 请求时间、数据时间；
- 响应耗时；
- 是否使用备用源；
- 是否发生字段冲突；
- 原始响应引用。

当前 `ProvenanceRecord` 没有完整承载响应耗时、原始响应引用和冲突信息，Adapter 虽然计算了耗时，也没有写入契约。

修改要求：扩展 Observation/Provenance 契约，并为每一次外部调用生成审计事件。

### 6.2 Analysis Engine 指标实现不完整

当前已经实现 ATR、支撑阻力等底层函数，但 `analysis_engine.py` 没有把它们接入最终结果。

需要补齐：

```text
OHLCV
→ MA / EMA / MACD / RSI / ATR
→ 波动率 / 最大回撤 / 支撑阻力
→ 技术信号 / 风险标记 / 结论
```

所有指标都必须记录参数、数据范围、算法版本和复权方式。

### 6.3 API 配置没有使用 `api_prefix`

`Settings` 提供了 `api_prefix`，但 FastAPI 路由仍然硬编码 `/api/v1`。应统一由应用工厂注册路由，避免配置与实际行为不一致。

### 6.4 代码注释和阶段状态需要同步

部分注释仍然写着“Phase 2 才接入真实 MCP”或“Phase 3 才使用 Summary Model”，与当前 Prompt v3.1 的阶段定义不一致。

修改代码时应同步更新：

- 模块 docstring；
- 节点说明；
- README；
- 架构文档；
- 测试说明。

## 7. 推荐修改顺序

### 第一阶段：恢复真实 MCP 子图可运行

1. 修复 RootState 内部字段；
2. 增加 Fake Gateway ReAct 测试；
3. 修复 MCP 响应 JSON 解析；
4. 修复协议错误和吞错 fallback；
5. 验证 primary/fallback/双失败三种场景。

### 第二阶段：接通主流程能力

1. 接入 ContextBuilder；
2. 接入完整 AnalysisInput 装配；
3. 标的解析改为 Gateway 调用；
4. 按 analysis_type 接入 Research Agent；
5. 将预算、Tool 次数、ReAct 轮次接入 Runtime。

### 第三阶段：接入生产运行时

1. 增加 MCP SDK 和交易日历依赖；
2. 实现 PostgreSQL/Redis Checkpointer；
3. 移除生产环境 Mock 持仓降级；
4. 确认 Java Data API 契约和认证；
5. 增加跨服务集成测试。

### 第四阶段：完善指标与可观测性

1. 补齐 ATR、支撑阻力等指标接线；
2. 完善 Observation Provenance；
3. 增加分页恢复、超时、冲突和降级事件；
4. 同步 README、Prompt、架构文档和代码注释。

## 8. 必须新增的回归测试

### 8.1 Market Data Graph

- Fake Gateway 成功调用并正常结束；
- action 在节点间正确传递；
- pending observation 能被 Normalizer 消费；
- ReAct 轮次达到上限后返回 LIMITED；
- market_snapshot 不进入 ReAct；
- primary 协议错误触发 fallback；
- `error=true` 触发 fallback；
- 主备均失败写入 `known_unavailable`。

### 8.2 AnalysisInput

- quote 正常解析；
- 历史 K 线正常解析；
- 财务、估值、行业、新闻字段正常装配；
- 字段缺失不会被伪造为成功数据；

- Mem0 search 失败时主流程继续；

### 8.5 外部服务契约

- SSE MCP Client；
- Streamable HTTP MCP Client；
- Java 持仓 API；

## 9. 完成标准

本修改方案全部完成后，必须满足：

1. Mock 流程和真实 MCP 流程都能结束；
2. 真实 MCP 不再触发 `GraphRecursionError`；
3. 原始 MCP JSON 不会直接进入 Analysis Engine；
4. 主源、备用源和双失败状态可追踪；
5. comprehensive 能按预算完成有限 ReAct；
6. market_snapshot 不启动 ReAct；
7. Mem0 失败不阻断主流程；
8. production 使用持久化 Checkpointer；
9. Java 服务异常不会生成伪造持仓结论；
10. AnalysisInput 所需数据域装配完整；
11. 交易日历和指标计算均有可复现测试；
12. Python、Java、Node、前端测试全部通过；
13. README、架构文档、Prompt 和代码注释保持一致。

## 10. 当前暂不处理内容

以下内容不纳入本轮主版本修复：

- Letta 对比 Runtime；
- 真实下单、撤单和交易执行；
- Node Skill 是否最终独立部署；
- 策略自动执行和生产级回测服务；
- 非必要的前端视觉改造。

本轮目标是先让 LangGraph + Mem0 + MCP 主版本形成可恢复、可追踪、可测试的闭环。
