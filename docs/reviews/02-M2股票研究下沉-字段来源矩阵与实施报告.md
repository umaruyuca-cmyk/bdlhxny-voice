## 1. 目标与边界

本阶段把 M1 Finance Runtime 已产生的 `Observation + AnalysisResult`，通过纯规则、可复现的 `StockResearchResultBuilder` 下沉为唯一权威的客观股票研究结果，并在 `FinancialDomainOutcome` 中继续保留 `analysis_result` 作为过渡双写字段。

本阶段仅覆盖 `STOCK_RESEARCH`、单标的以及 `market_snapshot / technical / fundamental / valuation / comprehensive` 五类分析。不会读取 `portfolio.*` 或 `user.*`，不会生成 Suitability、组合影响、交易指令、个性化建议、最终聊天文案，也不会修改默认 API、旧 Root Graph、Summary Model 或持久化方式。

## 2. 字段来源矩阵

| 结果字段 | 唯一允许来源 | 生成规则 | 缺失/异常处理 | 核心测试 |
|---|---|---|---|---|
| `instrument` | `FinancialDomainRequest.instruments[0]` | 原样复制标的身份 | 请求契约已保证恰好一个标的 | 五类分析均保持 symbol/name/market |
| `market_snapshot` | 已规划的 `market.get_realtime_quote` Observation | 映射 symbol/name/price/currency/date/source_time | 必需数据缺失时 section 为空、coverage LIMITED | 正常快照、行情不可用 |
| `fundamentals` | 已规划的 `market.get_financial_statements` Observation | 只映射可验证财务字段及质量 | 未规划则必须为空；已规划但不可用则记录 limitation | fundamental/comprehensive、非请求可选项为空 |
| `valuation` | 已规划的 `market.get_valuation` Observation | 映射 PE/PB/PS/method | 同上 | valuation/comprehensive、估值不可用 |
| `technicals` | 已规划的历史行情 Observation + `AnalysisResult.calculated_indicators/signals` | 不重算指标；仅投影已有确定性计算结果并推导趋势枚举 | 未规划历史行情时为空；指标不可用时保留限制 | technical/comprehensive 指标一致性 |
| `money_flow` | 已规划的 `market.get_money_flow` Observation | 映射净流入等客观字段 | 未请求且未规划时必须为空 | requested_topics 门控、comprehensive |
| `industry_context` | 已规划的 `market.get_industry_context` Observation | 映射行业与同业列表 | 未请求且未规划时必须为空 | requested_topics 门控、comprehensive |
| `events` | 已规划的 `market.get_news` / `research.web_search` Observation | 只提取受控 headline/source/time，生成稳定 event_id | 无可信标题则跳过，不把原始正文直接带入 | news/web_research 门控、异常文本 |
| `evidence` | 已规划且状态为 SUCCESS/PARTIAL 的 Observation | 每个 Observation 生成稳定 EvidenceFact；来源、时间、质量和引用可追溯 | 缺少 provenance 时使用固定回退时间并降级，不使用当前时间 | 证据引用、重复运行一致 |
| `findings` | `AnalysisResult.conclusions` + 已存在的 evidence/calculation refs | 纯确定性投影；每条 Finding 至少含 evidence_ids 或 calculation_ids | FAILED/LIMITED 或无引用时不生成结论 | 引用完整性、无 LLM 百分比 |
| `risks` | `AnalysisResult.risk_flags` | 严重度标准化，引用已有证据 | 不生成用户适配/交易风险结论 | 风险字段与证据引用 |
| `conflicts` | 同一已规划 capability 的重复成功 Observation | 比较预定义语义字段；值冲突时保留双方 EvidenceFact 引用 | 冲突不得静默覆盖；coverage/confidence 强制降级 | 显式双源价格/财务冲突 |
| `scenarios` | M2 无授权来源 | 固定为空列表 | 不允许由 LLM 或 Builder 编造 | 五类分析均为空 |
| `coverage` | `DataRequirement + Observation + AnalysisResult.status + conflict/data_mode` | 统一确定性状态矩阵 | 必需缺失/分析 LIMITED 为 LIMITED；冲突不得 COMPLETE | COMPLETE/PARTIAL/LIMITED 对照 |
| `confidence` | coverage、分析状态、来源质量、冲突 | HIGH/MEDIUM/LOW 枚举规则 | MOCK/UNAVAILABLE 不支持完整实时研究 | 正常、降级、冲突、非实时数据对照 |
| `limitations` | Runtime limitations + AnalysisResult limitations + Builder limitations | 稳定去重并集，只增不减 | 不得少于 `AnalysisResult.limitations` | limitations 非递减断言 |

## 3. 确定性状态策略

1. `AnalysisResult=FAILED`：研究 coverage 为 LIMITED/LOW，Outcome 为 FAILED/LOW。
2. `AnalysisResult=LIMITED` 或必需 Observation 不可用：LIMITED/LOW。
3. Observation PARTIAL 或 AnalysisResult PARTIAL：PARTIAL/MEDIUM（若更严重条件存在则服从更严重条件）。
4. 必需/已执行数据完整、AnalysisResult SUCCESS、无冲突、来源可用于实时研究：COMPLETE/HIGH。
5. 重复来源发生语义冲突：研究不得 COMPLETE，可信度不得 HIGH；高实质冲突降为 LOW。
6. MOCK/UNAVAILABLE 不得支持 COMPLETE；TEST_FIXTURE 最多支持 PARTIAL。
7. 已规划但没有可用 Observation 的 section 为空并增加限制；未规划的可选 section 即使收到游离 Observation 也必须为空。

## 5. 验收结果

- 五类分析的正常 fixture 均返回 `StockResearchResult`，状态为 COMPLETE/HIGH；每类必需能力不可用时均返回 LIMITED/LOW。
- 未规划的 money flow、industry、news/web Observation 即使游离进入 Builder，也不会填充可选 section 或 evidence。
- 重复行情来源价格冲突会生成 `EvidenceConflict`，保留双方 evidence refs，并降为 PARTIAL/LOW。
- `Technicals.indicators` 与过渡期 `AnalysisResult.calculated_indicators` 保持一致；Builder 不重算指标。
- Finding 全部至少含 `evidence_ids` 或 `calculation_ids`；FAILED/LIMITED 不生成伪结论；scenarios 在 M2 固定为空。
- Runtime、AnalysisResult 与 Research limitations 使用稳定去重并集，研究限制不会少于旧结果限制。
- 新闻/网页正文与 snippet 不复制到研究结果，只保留清洗后的标题及受控元数据。
- 未引入 Checkpointer，未修改默认 API、旧 Root Graph、Summary Model、聊天输出或个性化金融链路。
- Python 全量回归：`230 passed in 1.72s`（M2 前基线为 `217 passed`，新增 13 个有效测试）。
