# M6 最小持续任务实施报告

> 实施日期：2026-08-12  
> 状态：`DEVELOPMENT_COMPLETE / RELEASE_BLOCKED`  
> 唯一任务类型：`PRICE_THRESHOLD`

## 1. 本轮交付

- 严格 `FinancialTask`、价格条件、审计事件和 Notification Outbox 契约；
- `DRAFT → SCHEDULED → RUNNING → WAITING / TRIGGERED → COMPLETED` 状态机，另含
  `FAILED / CANCELLED / EXPIRED` 终态和非法迁移拒绝；
- 开发/测试内存 Store 与生产 PostgreSQL Task Store / Notification Outbox；
- 显式 migration `20260812_financial_tasks.sql`，包含到期索引、唤醒幂等表和通知唯一键；
- Scheduler 使用 `task_id + scheduled wakeup_at` 领取，`FOR UPDATE SKIP LOCKED` 支持多 Worker；
- Worker 崩溃后的 stale `RUNNING` 恢复，仍使用原唤醒槽，不跳过计划执行；
- `SCHEDULED_WAKEUP InputEvent` 进入 Cognitive Kernel，由 Finance `market_snapshot`
  路径重新获取本轮价格，不读取历史结论；
- 数据为 `PARTIAL / LIMITED / FAILED`、价格/时间缺失、质量低或币种不一致时进入
  `WAITING`，禁止确定通知；
- 条件满足后先写 Outbox，再完成任务；Outbox 按唤醒键去重，失败最多重试三次；
- JWT 用户隔离的创建、列表、查看、取消、审计和已发送站内通知查询 API；
- 创建必须由用户显式 `confirmed=true`，服务端生成 confirmation ref，并强制
  `Idempotency-Key`；相同键和不同请求返回冲突。

## 3. 发布门禁

代码默认 `BDLH_FINANCIAL_TASK_WORKER_ENABLED=false`。真实生产启用仍需：

1. 应用 PostgreSQL migration 并验证表存在；
2. 关闭 M0 的 Run Registry、Analysis History 与 Cognitive 上下文持久化缺口；
3. 完成真实 PostgreSQL 多 Worker / 重启故障注入；
4. 配置 Worker 指标、告警、owner、通知渠道和回滚演练；
5. M5 新 Cognitive 路径满足灰度门禁。

因此本阶段代码完成不代表真实通知流量已经启用。

## 4. 范围边界

- 未实现通用自动化平台、多条件组合、交易、调仓或下单；

- 当前 Outbox 默认发送器落为站内通知记录，外部邮件/短信/Push 需后续受控 Sender；
- M7 未开始。
