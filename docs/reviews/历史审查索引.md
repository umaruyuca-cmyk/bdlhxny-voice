## 3. 仍然有效的历史原则

以下原则已经进入当前架构或审查规范，仍然有效：

- 一个稳定契约只能有一个权威定义；
- 确定性计算由代码完成，LLM 只负责规划、解释和表达；
- Observation 必须携带来源、时间、质量和降级信息；
- Mock 只能用于开发/测试，生产不得伪装成真实事实；
- 客观股票研究与面向用户的适配性结论必须分离；
- 用户身份只能从可信认证上下文推导；
- 类型、Protocol 和目录骨架不等于运行时能力已经实现；
- 新架构必须渐进切流，旧路径只能在新路径通过生产门禁后删除。

## 4. 不再作为当前依据的内容

以下信息只能作为历史背景：

- 旧文件中的固定源码/测试文件数量；
- `09cabfc`、`42b0722`、`07cd351` 等旧提交上的“当前代码”判断；
- 原 23、26、27、31 号 Prompt 的执行顺序和唯一基线声明；
- 32 与 33 中互相冲突的前置条件判断；
- 已被统一生产架构替代的双 Runtime、目录草案或完整重建方案；
- 没有重新验证证据的“已解决”“待实施”状态。
