## P0-1 LLM 配置可配置化(env 真源 + 请求级模型)

**背景**:`deploy/.env`、`.env.example`、`docker-compose.yml:46-47`、`docker-compose.cloud.yml:26-27` 都在设置 `LLM_BASE_URL`/`LLM_MODEL`,但 engine 源码从不读取。`ab_eval.py` 的 `run_ab_eval` 调 `create_llm(api_key=..., model=model)` 不传 `base_url`,永远落到 `infra/llm.py:17` 硬编码的厂商端点——运营者把 base_url 指向内部网关时,流量仍带着真实 key 打到厂商公网。另有遗留兜底 `os.getenv("LLM_API_KEY") or os.getenv("DEEPSEEK_API_KEY")`,残留旧变量时会把 DeepSeek 的 key 打到 bigmodel 端点。

**配置分层(2026-08-24 落地:env 唯一真源,无任何代码级默认端点)**:

1. **服务端 env 是唯一真源**(dev 文件 / compose / 云 secret 注入):
   - `LLM_API_KEY`:必填,缺失即批次失败(现有 fail-fast 保持);
   - `LLM_BASE_URL`:**必填,缺失即明确失败**(`build_llm_from_env` 抛 `LLM_BASE_URL 未设置`;`create_llm` 返回 None 并记日志)——不设任何内置默认端点,漏配置在启动/调用点立即暴露,而不是静默打到别的厂商;
   - `LLM_MODEL`:默认 `Qwen/Qwen3.6-35B-A3B`(仅模型名缺省,不涉端点)。
2. **请求级可配置项只有 `model`**:`EvalBatchRequest.model` 已是请求字段,API 调用方可按批次指定模型;不传时取 env `LLM_MODEL` 的值。/lab 页**不提供**模型切换控件(账号级配置模块已删除,见下)。
3. **安全边界:`base_url` 与 `api_key` 不接受请求级传入**。请求可指定任意 base_url 等于让服务端把 key 发往任意地址(key 外发通道),这两项只走服务端 env。
4. **账号级 LLM 配置模块已删除**:`GET/PUT /api/v1/llm-config` 端点、`DataClient.get_llm_config/save_llm_config`、/lab 的提供商/Key/模型配置卡片全部移除;仅保留 `POST /api/v1/llm-config/test` 作为 env 只读连通性探测。data 服务侧 `LlmConfigController` 与 `llm_configs` 表成为休眠端点,下线需维护者删 Java 类并手动执行删表 SQL。

**涉及文件**:
- `engine/src/bdlh_runtime/evaluation/ab_eval.py`(`run_ab_eval` 内 LLM 构建段,约 :406;`main()` 的 `--model` argparse,约 :757)
- `engine/src/bdlh_runtime/run_api.py:63`(`EvalBatchRequest.model` 默认值)
- `engine/src/bdlh_runtime/infra/llm.py`(docstring 更新)
- `engine/tests/eval/`(新增测试)

**改动步骤**:
1. `ab_eval.py`:`create_llm` 调用改为
   `create_llm(api_key=os.getenv("LLM_API_KEY"), model=model, base_url=os.getenv("LLM_BASE_URL"))`,并在 `build_llm_from_env` 中对缺失 `LLM_BASE_URL` 抛 `RuntimeError`——同时删除 `DEEPSEEK_API_KEY` 兜底与 `DEFAULT_LLM_BASE_URL` 常量,缺 key 时的 `RuntimeError` 提示保持指向 `LLM_API_KEY`。
2. `run_api.py`:`model: str = Field(default_factory=lambda: os.getenv("LLM_MODEL", "Qwen/Qwen3.6-35B-A3B"), min_length=1, max_length=100)`。
3. `ab_eval.py` `main()`:argparse `--model` 默认值改为 `os.getenv("LLM_MODEL", "Qwen/Qwen3.6-35B-A3B")`。
4. `infra/llm.py` docstring:删 `/ DEEPSEEK_API_KEY` 字样,补充"base_url/模型由 `LLM_BASE_URL`/`LLM_MODEL` 环境变量提供(调用方读取)"。
5. 复核 `.env.example` 三个键齐全、无 DEEPSEEK 残留。

**落地状态(2026-08-24)**:已按上述口径实现——`DEFAULT_LLM_BASE_URL` 全仓清零;`create_llm` 缺 base_url/api_key 返回 None 并记日志;账号级 llm-config 端点、DataClient 方法与 /lab 配置卡片已删除(engine 397 + web 56 测试全绿)。

## P1-1 data 服务数据源 fail-fast + 本地隧道启动文档

**背景**:`data/src/main/resources/application.yaml:9-11` 的 `DATABASE_URL` 默认 `jdbc:postgresql://127.0.0.1:5432/touchstone`、`DATABASE_USER` 默认 `touchstone`、`DATABASE_PASSWORD` 默认空。该默认值实际服务于当前本地开发工作流——本地经 SSH 隧道连云端(隧道脚本 `D:\workbuddySpace\2026-08-16-14-56-01\ssh_tunnel.bat`:本地 `5432` → 云端 PostgreSQL,本地 `18080` → 云端 data 服务 8080)。问题在于:裸机/k8s 生产漏配变量时,服务会静默连 localhost 而非启动报错。方案:yaml 去默认值 fail-fast,本地开发方式(隧道)在 README 明示,显式传变量。

**改动步骤**:
1. `application.yaml:9-11` 三项去掉默认值:`url: ${DATABASE_URL}`、`username: ${DATABASE_USER}`、`password: ${DATABASE_PASSWORD}`(Spring 占位符无默认时缺变量即启动失败)。
2. `data/README.md` 增加"本地开发(经 SSH 隧道)"小节:
   - 先启动隧道(脚本属本机工件、含服务器地址与账号,**不复制入库**,README 只描述机制:本地 5432 转发云端 PostgreSQL、18080 转发云端 data 8080);
   - 启动 data 前 PowerShell 显式设变量,示例:
     ```powershell
     $env:DATABASE_URL = "jdbc:postgresql://127.0.0.1:5432/touchstone"
     $env:DATABASE_USER = "touchstone"; $env:DATABASE_PASSWORD = "<隧道目标库密码>"
     $env:DATA_INTERNAL_TOKEN = "<内部令牌>"
     mvn spring-boot:run
     ```
   - engine 本地连云端 data:`DATA_API_BASE_URL=http://127.0.0.1:18080/internal/v1`。
3. 检查 data 测试(现有 Controller 测试为切片测试,不连库):若有需要完整上下文的测试因缺变量失败,在该测试属性中显式提供占位 `DATABASE_*` 值,不得回改 yaml 默认值。

**验收**:`mvn -q test` 全绿;`data/README.md` 有隧道启动小节;`application.yaml` 三项无默认值;不注入变量直接 `mvn spring-boot:run` 在启动期报占位符解析失败(而非连接超时)。

## P1-3 Dockerfile 加固(非 root、EXPOSE)

**背景**:`engine/Dockerfile`、`data/Dockerfile` 均无 `USER`,容器以 root 运行;engine 缺 `EXPOSE 8090`(文档性)。

**改动步骤**:
1. `engine/Dockerfile`:`uv sync` 之后创建用户并赋权(注意 `ARTIFACTS_DIR=/app/artifacts` 写权限):
   ```dockerfile
   RUN useradd --create-home --uid 10001 appuser \
       && mkdir -p /app/artifacts && chown -R appuser /app
   USER appuser
   EXPOSE 8090
   ```
2. `data/Dockerfile` 运行阶段(JRE 镜像)同样加非 root 用户与 `EXPOSE 8080`;如 compose 以 volume 挂载工件目录,确认挂载点属主可写。
