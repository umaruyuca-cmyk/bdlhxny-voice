# 前端展示补充任务清单

依据 2026-08-21 前端完成度审计生成。设计真源:`docs/evaluation/Agent对照评测与证据展示.md`
(§11 公开展示、§12 发布校验、§9-10 工件与批次报告格式)与
`docs/showcase/固定用例与网页展示.md`(§13 网页展示设计)。

## 总体策略(所有卡片共同遵守)

1. **站点分为两层**:`/showcase`(实证层,数据驱动,本清单新建)与 `/docs`
   (架构讲解层,现有 8 页保留)。根路由 `/` 改指 `/showcase/`,`/docs` 保持可达。
2. **铁律(来自设计文档,违反即返工)**:
   - 公开页面纯静态、零后端调用、无输入控件(唯一例外:/lab 私有页,见 FE-9);
   - 页面数字一律来自 `showcase-data/` 静态产物,不手写、不估算;
   - 尚未运行的字段显示"未运行",不得用设计样例数字冒充实验结果(showcase 文档 §2.4);
   - 首页只展示"最新**有效**批次";没有满足门槛的批次时明示"尚无正式批次",
     不拿最新生成的批次顶上(评测文档 §11.1);
   - 不得只挑"基线失败、完整模式成功"的案例,提供全量入口(评测文档 §10)。
3. **数据管线**:发布脚本(P3-5 首版,FE-8)从运行工件投影生成
   `web/public/showcase-data/`;页面只读该目录。工件 validity 分类(P3-1)落地前,
   schema 以 `validity: "UNCLASSIFIED"` 诚实标注,页面据此不把批次当正式结果。

## FE-3 showcase-data JSON Schema v1 + 校验器

**背景**:页面渲染与发布脚本(FE-8)需要共同的数据契约。格式依据评测文档 §9(运行工件)、
§10(批次报告)、§13.4(showcase 文档公开工件字段)。schema 先行,页面与脚本都对着它写。

**涉及文件**:新建 `web/schema/showcase-data/`(JSON Schema 文件)、
`web/test/showcase-schema.test.js`。

**改动步骤**:
1. 定义三个 schema(字段从上述文档条目投影,公开工件禁止字段:
   完整系统提示、密钥、令牌、内部地址、未脱敏用户数据):
   - `index.schema.json`:`{ generated_at, formal_batches: [], latest_batch: {id, is_formal,
     validity_gate: {met: bool, reason}} | null }`;`formal_batches` 仅收满足有效样本门槛的批次;
   - `batch-report.schema.json`:`{ batch_id, experiment_type, fixed_conditions, groups:
     [{agent_mode | context_strategy, valid_runs, invalid_runs, metrics…}],
     outcome_counts: {win, regress, tie, both_fail, invalid}, cases: […全量]}`;
   - `run.schema.json`:按评测文档 §11.3 九段展示顺序组织:`fixed_input, context,
     visible_tools, model_steps, code_decisions, tool_results, output_checks,
     final_result, cost`;所有数量字段允许 null(未运行)。
   - 通用枚举:`validity: "VALID" | "INVALID" | "UNCLASSIFIED"`;
     `status: "COMPLETE" | "FAILED" | "INVALID" | "CANCELLED" | "PENDING_JUDGMENT" | "NOT_RUN"`。
2. 测试:合法样例通过、逐字段缺省/越权字段(如 `system_prompt`、`api_key`)被拒、
   null 字段合法(未运行)。校验器用 Node 内置(自写轻量 walker 或引入
   `ajv` devDependency——**仅 devDependencies,不进镜像**)。

**验收**:`npm test` 含 schema 用例且全绿;`web/schema/README.md` 一页说明三文件与禁止字段。

## FE-10 engine 私有 CORS(仅 /lab 需要)

**背景**:/lab 页面(8082)跨端口调用 engine(8090),浏览器预检需要 CORS;
engine 当前无 CORS 配置。公开部署永不启用。

**涉及文件**:`engine/src/bdlh_runtime/run_api.py`、`engine/tests/eval/test_run_api.py`。

**改动步骤**:
1. `FastAPI(...)` 加 `CORSMiddleware`,`allow_origins` 读
   `RUN_API_ALLOWED_ORIGINS`(逗号分隔,**默认空=拒绝所有跨域**),
   `allow_credentials=False`(用 Header 传 token,不需要 cookie),
   仅 `POST/GET`,`OPTIONS` 由中间件处理;
2. compose:本地/云私有形态 web 服务环境加
   `RUN_API_ALLOWED_ORIGINS: http://127.0.0.1:8082`(按实际 CONSOLE 绑定调整),
   公开形态无 engine,天然不受影响;
3. 测试:设置变量后预检 OPTIONS 204、未设置时无 CORS 头。

**验收**:`pytest tests/eval/test_run_api.py` 全绿;默认配置下跨域请求不带 CORS 头
(fail-closed)。
