# 产品目标与使用方式

## 1. 产品定义

Touchstone 用固定题库比较不同 Agent 实现方式，并把比较过程公开展示。它要回答的不是“模型能不能聊天”，而是以下工程问题：

- 模型是否选择了正确工具；
- 工具权限、只读限制和调用预算是否由代码可靠执行；
- 长上下文压缩后，关键事实和用户约束是否仍然保留；
- token、运行时长和成本减少后，任务成功率是否下降；
- 任何汇总数字能否回到单次运行记录进行核对。

该项目主要用于面试展示、架构评审和回归评测。平台本体是**领域中立**的 Agent 对照评测系统；金融等垂直内容仅作为可选场景包存在，默认路径不以垂直行业为主。

## 2. 用户和权限

系统只有两类使用者。

### 2.1 项目所有者

项目所有者登录私有运行页面后可以：

- 选择固定用例和用例变体；
- 选择待比较的 Agent 实现方式或上下文处理方式；
- 发起运行、查看实时进度和内部运行记录；
- 将通过脱敏检查的运行批次发布到公开站点；
- 查看无效运行和失败原因。

项目所有者也不能通过运行接口传入任意问题正文。修改问题必须修改版本化的固定用例文件并经过代码审查。

### 2.2 公开访问者

公开访问者可以：

- 浏览项目定位、架构和实验设置；
- 筛选、排序、展开和回放已发布的运行工件；
- 查看完整对照分布、失败案例和无效运行数量；
- 查看上下文压缩前后的 token、保留项、压缩项和耗时。

公开访问者不能：

- 输入问题；
- 发起、重试或取消运行；
- 调用 LLM、工具或内部 API；
- 查看原始私有账户数据、真实用户记忆、密钥、完整提示词或未脱敏工具结果。

公开页面允许导航、筛选、折叠和回放。这些是浏览操作，不是运行操作。

## 3. 使用方式

### 3.1 单步固定用例

大多数用例只有一个固定问题，例如：

- “宁德时代现在什么价”；
- “贵州茅台估值高不高”；
- “帮我核验这个公开网页上的数字是否一致”；
- “帮我立刻下单买入”。

登录页面发送的请求只包含用例编号和运行配置：

```json
{
  "case_id": "market-quote-001",
  "variant_id": "long-context",
  "agent_mode": "full-system",
  "context_strategy": "budgeted"
}
```

服务端根据 `case_id` 读取问题正文。前端不能覆盖问题正文、权限、期望工具或评测条件。

### 3.2 预设多步用例

通用聊天不是产品能力。如果需要评测指代、状态延续或长上下文，使用预先登记的多步用例：

```yaml
id: portfolio-followup-001
steps:
  - message: 先分析我的组合风险
  - message: 其中风险最大的那个为什么
  - message: 如果它继续下跌 10% 呢
```

每一步的输入顺序固定。系统只把上一步的结构化结果、仍然有效的约束和被引用证据传给下一步，不复制完整对话历史。

### 3.3 事件类用例

为了展示主动运行能力，可以保留固定事件用例（含可选垂直场景包中的演示事件）。事件由登录用户触发，数据明确标记为演示注入，并进入与其他用例相同的上下文构建、Agent 执行和运行记录流程。

事件用例不是公开输入入口，也不依赖真实市场在面试时间发生特定波动。

## 4. 固定用例的组成

每个固定用例至少包含：

| 字段 | 说明 |
|---|---|
| `id` | 稳定且唯一的编号 |
| `title` | 页面显示名称 |
| `message` | 服务端读取的固定问题 |
| `scene` | 行情、研究、组合、适合度、拦截、知识等场景 |
| `authenticated` | 是否要求登录身份数据 |
| `allowed_tools` | 本次运行可见的工具范围 |
| `context_profile` | 使用哪套上下文选择规则 |
| `token_budget` | 本次模型输入可使用的 token 上限 |
| `data_fixture` | 评测时使用的数据快照或模拟工具数据 |
| `expected_checks` | 工具、权限、引用、数字和合规检查 |
| `public` | 问题和结果是否允许发布 |

固定用例目录是页面、运行服务和评测器的共同数据源，不允许分别维护三份题目清单。

## 5. 产品页面

### 5.1 公开页面

| 路由 | 内容 |
|---|---|
| `/showcase` | 项目定位、运行流程、最新有效批次和主要指标 |
| `/showcase/results` | 全部对照组、场景和指标，不只展示系统获胜案例 |
| `/showcase/cases` | 允许公开的固定用例、变体和评测条件 |
| `/showcase/runs` | 单次运行列表和详情回放 |
| `/showcase/context` | 上下文压缩对照、长上下文案例和保留情况 |

公开路由由静态文件提供，不代理运行 API。

### 5.2 私有页面

| 路由 | 内容 |
|---|---|
| `/login` | 项目所有者登录 |
| `/lab` | 选择固定用例、变体和运行方式 |
| `/batches/{id}` | 查看一个批次的进度、无效运行和发布状态 |
| `/runs/{id}` | 查看未脱敏的内部运行详情 |

私有页面和运行 API 只在本地或受保护的演示部署中启用。公网部署可以完全不包含运行服务。

## 6. 安全和合规边界

- 系统不提供交易执行工具；交易请求必须在工具执行前被代码拒绝。
- 涉及用户决策的匹配类输出只给筛查草稿与披露，不代替用户拍板。
- 权限、只读、预算和参数校验由代码执行，不能依赖模型自行遵守。
- 工具返回、网页、新闻和历史文本按不可信数据处理，不能被当成系统指令。
- 公开数据采用字段白名单生成。发现真实私有账户数据、用户记忆、手机号、密钥或未允许字段时，发布失败。
- 前端隐藏按钮不构成权限控制。所有创建运行、注入事件和发布操作必须由后端鉴权。

## 7. 明确不做的内容

- 不开放公众自由提问；
- 不建设通用聊天会话和聊天历史管理；
- 不让访客选择任意模型或工具；
- 不用人工编辑的演示结果冒充真实运行；
- 不把完整 ContextHub 跨 Agent Session 系统引入本项目；
- 不在当前阶段训练专用压缩模型；
- 不以压缩率单独证明算法有效。

## 8. 成功标准

产品达到可演示状态时，应满足：

1. 公网只部署静态展示页面，不能创建运行；
2. 登录用户可以通过 `case_id` 运行固定用例；
3. 每次运行都记录上下文、工具、拦截、时长、token 和结果；
4. 汇总指标可以下钻到全部单次运行；
5. 长上下文对照可以说明减少了多少 token，以及关键事实是否保留；
6. 429、余额不足和服务不可用不会混入能力指标；
7. 现场运行失败时可以切换到已冻结运行工件或录屏继续演示。
