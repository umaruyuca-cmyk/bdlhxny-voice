## 2. `docs/`（新纪律：最小文档集）

```text
docs/
├── 00-仓库文件管理树.md                  ACTIVE         本文档（docs 根目录唯一文件）
├── architecture/
│   └── 00-Sentinel产品设计与架构.md       AUTHORITATIVE  唯一设计真源（产品 + 架构 + 契约 + 路线）
├── prompts/
│   └── 00-Sentinel实施Prompt.md          ACTIVE         实施期唯一执行真源（工单集与状态机）
└── eval/                                               eval 对照报告（随首份报告创建，YYYYMMDD_主题.md）
```

规则：

1. docs 根目录只保留本文档；设计文档落 `architecture/`，执行指令落 `prompts/`，eval 报告落 `eval/`；
2. **设计内容只进 `architecture/00` 号文；执行指令与工单状态只进 `prompts/00` 号文**；不新增并行设计文档，不新增「实施报告」类文档（实施记录以工单回填与 Git 提交承载）；
3. `docs/prompts/`（执行指令文档）与 `sentinel-engine/prompts/`（prompt 代码资产）是两个位置，不得混用；
4. 组件级文档（各服务 README、部署手册）留在组件目录，不进 docs/；
5. 不再设 `reviews/`、`archive/` 子目录——历史分类已随旧文档清除，Git 追溯。

## 4. 其余组件的文件归属

| 目录 | 规则 |
|---|---|
| `sentinel-data/` | 标准 Spring Boot 布局；内部 API 在 `/internal/v1` 下，对外在 `/api` 下 |
| `sentinel-console/` | `public/` 为页面与资产；`test/` 为契约测试；`CHAT_INTEGRATION.md` / `API_INTEGRATION.md` 按设计文档 §6.2 / §7 描述 SSE 契约 v2 与页面路由。`public/skills/` 为开发遗留，非产品入口（2026-08-19） |

| `deploy/` | 两套 compose（本地 / 云端）、`.env.example` 为唯一配置清单真源、`DOMAIN_DEPLOYMENT.md` 为域名与端口收口手册、`rocketmq/README.md` 为 MQ 运维说明 |
