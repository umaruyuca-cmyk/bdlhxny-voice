# Touchstone 文档目录

> 状态：当前设计入口；旧方案仅在明确标注的历史文档中保留  
> 适用分支：`touchstone`  
> 更新日期：2026-08-24

Touchstone 是一个面向 Agent 工程实践的固定用例评测与展示系统。项目所有者和受限匿名访问者可以运行预先登记的公开用例，系统记录模型输入、上下文压缩、工具调用、代码拦截、运行时长和最终结果。访问者不能输入任意问题；匿名结果只保存在“我的测试”中，不会自动成为正式公开结果。

本目录只保存产品与工程设计。评测结果、运行记录和录屏不放在 `docs/` 中，避免把设计与实验产物混在一起。数据库设计单独放在 [`db/`](../db/README.md)。

## 五个核心决定

1. **不提供公开输入框。** 匿名访问者只能选择公开的固定用例或固定 Session，不能提交任意问题。
2. **运行只接受固定编号。** 请求提交 `case_id` 或 `session_id`，正文由服务端按版本读取，不能从请求中传入任意问题。
3. **实验以模板定义。** 正式实验 = 实验模板 + 唯一自变量。统一原生 Tool Calling 底座、模型、工具目录、Mock 和评判规则作为固定条件；默认上下文实验为 4 种上下文方式 × 1 种固定执行配置（4×1）。
4. **上下文按预算构建。** 系统先收集原始数据，再按场景保留、压缩或引用，最后生成模型实际使用的上下文。
5. **结果必须可以追溯。** 汇总指标可以下钻到单次运行；无效运行、失败案例和完整对照分布都必须保留。

## 常用术语

| 术语 | 本文中的含义 |
|---|---|
| 固定用例 | 由仓库预先登记的问题、场景、权限、工具范围、上下文来源和评测条件 |
| 压缩用例 | 上下文压缩模块中的三个固定长 Session，可只生成上下文，也可运行 4×1 上下文策略模板 |
| 对比用例 | 用例库中的普通固定问题，选择一个单变量实验模板后按模板范围重复运行 |
| 重复次数 | 相同实验条件创建多少个独立运行，字段名为 `repeat_count` |
| Agent 最大步数 | 一次运行中模型判断和工具结果回传的上限，字段名为 `max_agent_steps`，不等于重复次数 |
| 用例变体 | 同一个问题在短上下文、长上下文、冲突数据或故障条件下的不同输入数据 |
| 数据快照 | 一次运行使用的固定上下文和冻结工具数据版本 |
| 运行配置快照 | 一次运行的完整配置（`RunConfig`，含请求/生效参数与工具排除项），规范化序列化后取 `config_hash` |
| 原始上下文 | 运行可使用的全部候选信息，通常不能全部发送给模型 |
| 工作上下文 | 经过选择和压缩后，实际发送给模型的信息 |
| 上下文条目 | 一条带来源、时间、类型、重要性和 token 数的信息 |
| 运行记录 | 一次运行的输入条件、上下文处理、模型轮次、工具调用、拦截、结果和指标 |
| 运行工件 | 冻结为 JSON 的运行记录，用于评测、回放和公开展示 |
| 无效运行 | 因 429、余额不足、服务不可用或评测器失败而不能用于能力统计的运行 |

## 文档和数据的存放规则

| 内容 | 目标位置 | 是否进入公开站点 |
|---|---|---|
| 设计文档 | `docs/` | 否，供开发阅读 |
| 固定用例定义 | `data` 的 PostgreSQL 版本表 | 只发布允许公开的标题和问题 |
| 本地原始运行工件 | `engine/var/artifacts/` | 否，默认加入 `.gitignore` |
| 公开运行工件 | `web/public/showcase-data/` | 是，由发布脚本生成 |
| 录屏 | `recordings/` | 按部署方式单独托管，不进入设计目录 |

## 各目录边界

| 目录 | 应该写什么 | 不应该写什么 |
|---|---|---|
| `product/` | 用户、权限、使用流程、产品边界 | 类和函数实现细节 |
| `architecture/` | 模块职责、调用关系、部署边界、运行流程 | 数据表完整字段清单 |
| `context/` | 上下文组成、预算、压缩、校验和降级 | Agent 对照结论 |
| `evaluation/` | 实验变量、有效性、指标、工件和发布规则 | 手工填写的最新实验数字 |
| `showcase/` | 固定案例、正反例、页面内容和展示数据 | 公开访客输入功能 |
| `development/` | 开发阶段、差距、测试清单和验收条件 | 重复其他目录的详细设计 |

## 文档维护规则

- 目录索引中列出的主题文档共同构成产品与工程设计，不再保留互相冲突的历史规则。
- 旧多实现对照方案只允许留在带有“历史文档”标记的资料中，不得作为当前接口、数据结构或运行流程的说明。
- 新术语必须在首次出现时用普通语言解释；能用“固定用例”“上下文条目”“运行记录”表达时，不创建新的品牌化名称。
- 代码与设计不一致时，在 [`development/开发计划与验收标准.md`](./development/开发计划与验收标准.md) 登记差距，不在多份文档中复制不同版本的结论。
- 评测数字只来自机器生成的运行工件。设计文档不手写“最新结果”。
