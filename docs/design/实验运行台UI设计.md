# 实验运行台 UI 设计

## 1. 设计目标

实验运行台不是聊天页面，也不是自由配置的模型调试器。它只负责从固定用例和版本化实验模板创建可复现的 Agent 对照批次。

页面需要让使用者在发起前回答清楚五个问题：

1. 本次实验研究什么问题。
2. 唯一改变的条件是什么。
3. 选择了哪个固定用例和哪些变体。
4. 实际会执行多少次、使用哪些固定条件。
5. 哪些参数已经传给运行时，哪些参数尚不支持。

## 2. 信息架构

运行台采用一个页面、五个工作区，不再把所有功能堆在同一张表单中。

### 2.1 运行概览

展示登录身份、模型连接状态、实验定义版本、当前任务状态和标准操作流程。这里只提供状态和入口，不直接发起实验。

### 2.2 正式实验

正式实验是页面主区域，采用左右两栏：

- 左侧：按研究方向展示可运行模板。
- 右侧：配置固定用例、重复次数和模板允许的少量高级条件。

操作顺序固定为：

```text
选择模板 → 选择固定用例 → 预估批次 → 核对配置 → 发起运行
```

未经预估不能发起。模板、用例、重复次数或高级条件变化后，原预估立即失效。

### 2.3 参数能力

参数按三种状态展示：

- 已接入：运行时会把参数传给 SDK 或 Agent 循环。
- 固定：第一版由模板冻结，不能在页面自由修改。
- 暂未支持：不会传给 SDK，也不能在页面输入。

页面不能把“配置对象里存在字段”描述为“运行时已经生效”。正式证据以批次预估和运行记录中的 requested、sent、unsupported 为准。

### 2.4 长上下文实验

长上下文与普通对比用例分开：

- 只压缩：在长上下文库中生成四种上下文，不调用 Agent。
- 压缩效果实验：在同一原生 Tool Calling 底座上比较四种上下文策略。
- 历史交叉诊断：保留旧 4×2 入口，但明确标记为多变量诊断。

### 2.5 历史诊断

`baseline/full-system` 等旧入口默认折叠。它们用于历史回归，不作为正式单变量实验，也不进入公告默认结论。

### 2.6 任务与证据

页面底部统一展示当前任务、批次运行列表和单次运行详情。运行详情需要包含：

- 模板、变体、配置哈希。
- requested/sent/unsupported 参数。
- 模型调用、工具调用、治理检查和事件流。
- token、耗时和停止原因。

## 3. 视觉结构

桌面端布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ Agent 实验运行台                 模型状态  当前身份  退出     │
├────────────┬─────────────────────────────────────────────────┤
│ 运行概览   │ 页面标题 / 当前状态                             │
│ 正式实验   │                                                 │
│ 参数能力   │ 模板列表                 批次配置                │
│ 长上下文   │ [治理] [工具] [温度]     用例 / 重复 / 预估     │
│ 历史诊断   │ [轮次] [能力退化]         运行数 / 变体 / 哈希   │
│ 任务证据   │                                                 │
└────────────┴─────────────────────────────────────────────────┘
```

移动端取消固定侧栏，导航变为横向滚动；模板和配置改为单列。

## 4. 模板展示规则

模板名称使用普通中文，技术编号作为次要信息：

| 模板编号 | 页面名称 | 研究方向 |
|---|---|---|
| `governance-on-off` | 治理开关对照 | 治理 |
| `tool-delivery-comparison` | 全量工具与工具搜索 | 工具提供方式 |
| `temperature-stability` | 温度稳定性 | 模型参数 |
| `tool-availability-degradation` | 工具缺失与替代路径 | 工具可用性 |
| `max-agent-steps-stability` | Agent 最大轮次 | Agent 循环 |
| `context-strategy-comparison` | 四种上下文策略 | 上下文 |

每张模板卡只展示研究问题、唯一变量、变体和预计运行规模。完整冻结配置放到预估结果中，不在模板列表堆叠 JSON。

## 5. 交互约束

1. 页面不接受问题正文、系统提示词、API Key 或自定义工具定义。
2. 正式实验只能引用固定题号和模板编号。
3. 只有模板白名单内的高级条件可以修改，并使用普通表单控件，不要求用户编写 JSON。
4. 发起按钮在预估成功前保持禁用。
5. 修改任何影响计划的字段后必须重新预估。
6. 运行是后台任务；离开页面不会主动取消，重新进入后可查看任务状态。
7. 历史诊断与正式实验在视觉、文案和结果标签上必须区分。
8. 页面不自动运行任何实验。

## 6. 第一版参数展示

第一版重点展示以下参数：

- LLM：model、temperature、max_output_tokens、timeout。
- Agent：max_agent_steps、max_tool_calls、max_calls_per_tool、运行时限。
- 工具：tool_delivery、search_top_k、excluded_tools、工具目录版本。
- 上下文：context_strategy、token_budget。
- 治理：governance_profile。

`top_p`、`seed`、`reasoning_effort`、动态 `tool_choice` 和开启并行工具调用，在适配器真正接入前只显示“暂未支持”，不提供输入控件。

## 7. 验收标准

- 默认视图中不再出现“一键运行旧口径”作为主操作。
- 正式模板与历史诊断明显分区。
- 用户无需阅读代码字段即可理解模板作用。
- 页面能准确显示变体数量和精确运行数。
- 参数未接入时不显示为已生效。
- 预估失效、提交失败、后台运行、取消和完成都有明确状态。
- 页面不包含自动测试或自动发布行为。
