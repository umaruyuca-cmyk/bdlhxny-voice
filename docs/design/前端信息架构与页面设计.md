## 一、现状问题清单

当前站点 39 个页面、11 个导航分组,是在"三种 Agent / 4×3 / 12 格"旧口径上逐次叠加出来的,与 11 号文稿"模板 + 唯一自变量"的新口径已经脱节。冗余集中在六类:

### 1. 整页重复

| 重复组 | 页面 | 问题 |
| --- | --- | --- |
| 指标定义 | `judging/index` ≡ `judging/metrics` | 9 行指标表逐字重复,后者自述"定义详见前者" |
| Session 交叉验证 | `session-cross/index` ↔ `experiment/compression` + `context/library` | 同一矩阵讲三遍;session-cross 仍是过时的 4×3 口径(LangGraph 在列)、全空无数据 |
| 工具目录 | `tools/index`(真数据)↔ `engine/tools`(静态构成表)↔ `engine/catalog`(ToolCard 说明) | 同一目录三处呈现;导航组名"工具目录"与 engine 子项"工具目录"撞名 |
| 实例展示 | `showcase/index` + `showcase/tools`(全空框架)↔ `cases/detail` | "固定输入+期望行为"概念重复,showcase 无任何数据 |

### 2. 跳转残页(5 个,纯 meta refresh)

`experiment/index`、`showcase/results`、`showcase/runs`、`session-cross/inputs`、`session-cross/results`。

### 3. 双发起入口并存

- 匿名入口:`experiment/compression`(4 个发起按钮)、`experiment/comparison`(用例+重复次数)。
- 私有入口:`lab/index`(模板浏览器 + 历史旧表单 + context-batches)。
- 两者能力不一致、口径文案各写一套;11 号 D2 要求"发起入口改为选择实验模板",当前只有 lab 做到了。

### 4. 空壳结果页

`context/results`、`showcase/*`、公告页五个"尚未发布"区块——同一 publications 索引被多个空壳重复读取。

### 5. 导航口径腐坏

- `session-cross/index` 内嵌旧版 side-tree,含 `/experiment/cases`、`/experiment/reproduce` 死链;
- `about/banks` 链接死链 `/experiment/cases`;
- `experiment/index` 不在导航内;
- 11 个分组中"实例展示"整组全空或过时。

### 6. 结果展示口径落后

现有结果按旧 `agent_mode` 分组展示;11 号 D3 要求按**模板变量**分组,首屏必须展示实验目的、模板版本、唯一自变量、固定条件摘要、`config_hash`、请求/生效参数、可见工具与 Schema 哈希——当前无任何页面承载这些信息。

## 二、设计原则

从 11 号文稿提取的六条硬约束,作为所有页面设计的验收标准:

1. **不是聊天产品。** 全站没有自由输入框;匿名与登录用户都只能运行版本化固定用例 / 固定长 Session / 固定模板。
2. **一个发起入口。** 全站只有"实验发起"一条路径(模板 → 变体 → 精确运行数 → 提交),`lab` 与 `experiment` 合并为同一页面的两种角色视图。
3. **单变量是默认,交叉是例外。** 页面默认只呈现单变量模板;多变量交叉必须挂"专项交叉·不能做单变量归因"标记,历史诊断模板挂"非严格单变量"标记。
4. **首屏即口径。** 任何批次结果页首屏必须回答:这个实验在比较什么(唯一自变量)、冻结了什么、`config_hash` 是什么、请求的和实际生效的参数各是什么。
5. **未发布即空态,不造占位。** 沿用公告页现有"尚未发布"口径,但收敛到唯一入口;不再保留第二套空壳矩阵页。
6. **历史可读但明确标记。** 历史批次标"旧实验定义",`baseline/full-system` 标"整体实现方案诊断",不重算、不改名、不冒充实测。
7. **文案分层:专业书面语为主,通俗注解为辅。** 语气对标主流大模型厂商的评测/文档产品,不用口语比喻(如"安检""摆出来"),也不堆砌开发者黑话:
   - **第一层(默认可见)**:专业书面语。模板标题用规范名词短语(如"长上下文记忆策略对比""工具调用治理的有效性验证"),说明用一句话讲清"比较什么、为什么",变体用规范中文名(如"治理关闭 / 标准治理""全量装载 / 检索式装载"),指标保留正式名称(应拦截召回率、误拦截率)。
   - **第二层(技术口径)**:模板 ID、版本、变量名、哈希等精确口径,以等宽小字跟在每层内容后面(如卡片底部一行 `tool-delivery-comparison v1 · variable: tool_delivery`),供复核与复现,不占主视觉。
   - 可能出现歧义的术语在首次出现处给一句话注解;注解是补充,不替代正式名称。
8. **导航可逆。** 任何从列表进入的二级页面(发起页、批次详情)左上角必须有"← 返回上级"入口;浏览器前进后退与视图状态一致;不允许出现"进入后回不来"的死胡同页面。

## 三、目标信息架构

39 页收敛为 **5 个一级模块、16 个页面**。导航侧栏同步收敛为 5 组。

```text
公告                /                          (保留,收敛空态)
实验                /experiment/               模板中心(列表)
  └ 发起            /experiment/run            统一发起页(匿名/所有者同页不同权限)
  └ 批次结果        /experiment/batches        批次列表(我的+公告)
                   /experiment/batch          批次详情(结果首屏+下钻)
我的测试            /test/                     (保留,并入批次列表入口)
数据资产
  ├ 用例库          /cases/ + /cases/detail    (保留)
  ├ 工具目录        /tools/ + /tools/detail    (保留,吸收 engine/tools、engine/catalog)
  └ 长上下文库      /context/library           (保留,吸收 context/results)
文档
  ├ 系统与复现      /docs/about                合并 about×3
  ├ 引擎与治理      /docs/engine               合并 engine×6 → 单页锚点
  ├ 上下文压缩      /docs/context              合并 context/index + context/design
  ├ 评判与口径      /docs/judging              合并 judging×4 → 单页锚点
  └ 数据与运维      /docs/ops                  合并 ops×5 → 单页锚点
```

### 删除清单(连页面带导航项)

| 删除 | 去向 |
| --- | --- |
| `session-cross/`(3 页) | 口径过时,由 `/experiment/run?template=context-strategy-comparison` 与 `/context/library` 覆盖 |
| `showcase/`(4 页) | 全空框架;代表性实例未来由公告页从正式批次内选择,不另建页面 |
| `judging/metrics` | 并入 `/docs/judging` |
| `engine/tools`、`engine/catalog`、`engine/loading`、`engine/governance`、`engine/guardrail`、`engine/index` | 并入 `/docs/engine` 单页锚点 |
| `context/index`、`context/design`、`context/results` | 并入 `/docs/context`;实测表归入 `/context/library` |

## 四、核心页面设计

### 4.1 模板中心 `/experiment/`

全站实验的唯一入口列表。替代现有 `experiment/compression`、`experiment/comparison` 的"入口页"角色。

**区块:**

1. **口径说明条**(固定文案,一段话):本系统以"实验模板 + 唯一自变量"定义正式实验;每个模板只改变一个变量,其余条件冻结;不生成参数笛卡尔积。
2. **模板卡片列表**,数据源 `GET /api/v1/experiment-templates`。每卡展示(遵循第二节原则 7 的文案分层):
   - **标题**:普通话问句(如"长对话里,AI 怎么'记住'之前聊的内容?");
   - **说明**:一段日常语言讲清实验在比较什么、为什么值得比较;
   - **比较项**:熟词写法的自变量与变体(如"比较的是:记忆方式 → 全部内容 / 只记最近几轮 / 一份摘要 / 按预算挑重点");
   - **技术口径行**(等宽小字,卡片底部):`template_id + 版本 + 自变量名`;
   - **类型徽章**(三选一,配色固定):
     - `正式单变量`(绿)— 6 个内置模板;
     - `专项交叉`(橙)— 多变量诊断,标注"不能做单变量归因";
     - `历史诊断`(灰)— `legacy-implementation-profile-diagnostic`,标注"非严格单变量";
   - 权限标记:`免登录可用` / `仅登录所有者`;
   - 操作:`发起实验 →`(按权限置灰)。
3. **我的最近批次**(登录后)/ **我的最近测试**(匿名,localStorage 身份),各 3 条,点击进入批次详情。

**空态:** 模板接口不可用时显示"模板注册表不可读"并停用所有发起按钮——模板是代码常量,接口失败即系统异常,不给降级表单。

### 4.2 统一发起页 `/experiment/run?template=<id>`

合并 `lab/index` 与 `experiment/compression|comparison` 的全部发起能力。这是 11 号 D2 的直接落地。

**布局:左上角"← 返回实验模板";左栏"实验定义(由模板固定,不可修改)" + 右栏"批次配置" + 底部"预估与提交"。**

**左栏(只读,模板即法律):**

- 这个实验在比较什么(普通话一段);
- 比较项与变体(熟词写法,如"安检开关 → 不设防 / 全程安检");
- 保持不变的条件(普通话逐条:同一个 AI 循环、同一个模型、同一份工具目录、同一份冻结数据……);
- 技术口径行(等宽小字):模板 ID + 版本 + 自变量名 + engine/fixture/judge 版本;
- 类型徽章与口径提示(历史诊断模板此处重复一次"非严格单变量"警告条)。

**右栏(可填,按模板白名单渲染):**

| 字段 | 说明 | 匿名 | 所有者 |
| --- | --- | --- | --- |
| 用例 / Session 选择 | 显示为"选择考题(系统固定题库,不能自己出题)",选项用日常名称+规模描述 | ✓ | ✓ |
| 重复次数 | 显示为"每道题重复跑几遍",范围由模板限定(如温度模板 3 或 5) | ✓ | ✓ |
| 工具排除预设 | 仅 `tool-availability-degradation` 模板出现,显示为"工具缺失档位";匿名只能选预设 | 仅预设 | 预设 + 允许列表内新建 |
| 高级设置(折叠) | 模板 `advanced_whitelist` 内的字段,如 `max_tool_calls`、`max_calls_per_tool`、`search_top_k` | ✗(不渲染) | ✓ |
| 变体数组 | **任何角色都不可编辑**;客户端不允许上传任意变体 | ✗ | ✗ |

**底部预估条(提交前必显):**

- 精确运行数:`{变体数} 个变体 × {重复次数} 次 = {N} 次运行`(对应 11 号"提交前必须显示精确运行数量");
- 角色/模板/批次上限校验结果;超限直接禁用提交并说明原因;
- `提交` 按钮:先 `POST /plan` 拿预估 → 用户确认 → `POST /template-batches` 或匿名 `POST /api/v1/public/test-jobs`;
- 提交后跳转批次详情页;**断开页面不停止后台任务**(页面明确提示)。

**压缩对照的特殊形态:** `context-strategy-comparison` 模板在右栏多一个选项——`只生成四份上下文(不运行 Agent)`,与 11 号 D1"生成完成后不自动运行 Agent"一致;勾选后预估运行数显示为"4 份上下文工件"。

### 4.3 批次列表 `/experiment/batches`

- 两个 Tab:`公告批次`(已审核发布的正式批次)/ `我的批次`(匿名测试与所有者未发布批次)。
- 行内字段:批次号(短哈希)、模板名+版本、类型徽章、自变量=变体数×重复数、状态、创建时间。
- 历史批次行尾挂 `旧实验定义` 灰色标记(11 号 D2)。
- 匿名身份只显示自己的批次;公告 Tab 所有人可读。

### 4.4 批次详情 `/experiment/batch/<id>`(结果首屏,11 号 D3 的直接落地)

左上角"← 返回批次列表"。

**首屏(口径卡,按顺序固定,文案分层):**

1. 这个实验在比较什么(普通话一段);
2. 比较项与变体(熟词写法;多变量交叉显示"多变量诊断"标记);
3. 保持不变的条件(普通话逐条);
4. 类型徽章(历史诊断模板置顶"整体实现方案诊断,非严格单变量"警告条;匿名批次置顶"个人测试 / 非正式结果"标记);
5. 技术口径行(等宽小字):模板 ID + 版本、自变量名、`config_hash` 与固定条件哈希(复制按钮)、可见工具数、排除项、工具 Schema 哈希、Schema Token;
6. **请求参数 vs 实际生效参数对照表**(参数名属技术层,保留原名,但"说明"列必须普通话):

   | 参数 | 请求值 | 生效值 | 说明 |
   | --- | --- | --- | --- |
   | temperature | 0.1 | 0.1 | — |
   | seed | 42 | null | 模型不支持,未生效 |

   生效值为 `null` 的行必须显示普通语言原因,不允许静默忽略;
7. **第二屏:按模板变量分组的结果矩阵**(不再按 `agent_mode` 分组;表头用普通话问句,如"该拦的拦住了吗",技术指标名放第二层):

- 单变量模板:行=变体值,列=核心指标(成功率/Token/时长/治理指标等,指标集由模板定义);
- 每格可下钻到单次运行:工具调用链、参数来源、冻结 Mock 返回、Token、耗时、停止原因;
- 治理类模板额外显示:应拦截召回率、误拦截率、未确认写入次数、`bypassed` 事件计数、审计完整率;
- 工具搜索模板额外显示三段归因:检索错误 / 选择错误 / 调用错误;
- 压缩模板显示:四方式压缩前后 Token 表 + 构建耗时 + 遗漏项。

**空态与失败态:** 批次进行中显示进度与已完成的运行;固定条件被变体覆盖导致"执行前失败"的批次,显示失败原因而非空矩阵(11 号 A3:执行前失败,不等结果生成后才警告)。

### 4.5 公告 `/`(收敛,不大改)

保留现有结构与"尚未发布"口径,但做两处收敛:

- 五个"尚未发布"空区块合并为一个发布公告区 + 事实卡;不再分五段重复占位文案;
- 正式发布后,公告各汇总区直接链接到 `/experiment/batch/<id>` 的公告视图,不再在公告页内维护第二套结果组件。

### 4.6 我的测试 `/test/`(保留,微调)

- 保留任务列表、5s 轮询、取消、展开明细;
- 页面顶部增加一行入口:"这些是个人测试,不会进入公告;查看公告批次 →";
- 已完成任务的"展开结果"直接跳 `/experiment/batch/<id>`,不再在列表内嵌第二套结果渲染。

### 4.7 数据资产三页(保留,小幅增强)

- `/cases/`、`/tools/`、`/context/library` 保留现有表格与筛选;
- 详情页增加"在哪个模板里被使用"反向链接(如工具详情显示被哪些排除预设引用);
- `/context/library` 吸收原 `context/results` 的四策略实测表,成为压缩数据的唯一展示页。

### 4.8 文档五页(合并碎页)

每页统一版式:顶部锚点目录 + 长文。合并映射见第三节删除清单。合并时必须完成 11 号 D4 的口径清理:删除"三种 Agent / 4×3 / 12 格"的现行语气,改为历史说明;`scoped` 统一改述为"场景预筛策略,非全量工具";`baseline/full-system` 统一改述为"整体实现方案诊断"。

## 五、全站共享组件约定

1. **类型徽章**:`正式单变量`(绿)/ `专项交叉`(橙)/ `历史诊断`(灰)/ `旧实验定义`(灰描边)/ `个人测试·非正式`(蓝)。全站只有这五种,文案固定,禁止页面自造。
2. **哈希 chip**:`config_hash`、Schema 哈希、工件哈希统一等宽 8 位短显 + 悬停全量 + 点击复制。
3. **请求/生效对照表**:固定四列(参数/请求/生效/原因),全站复用;生效=null 必须填原因。
4. **空态**:只有两种——"尚未发布"(公告域)与"尚未运行"(数字占位)。禁止估算数字冒充实测。
5. **权限视图**:同一页面按角色渲染,不为匿名和所有者各做一套页面;匿名不渲染的字段(高级设置)在 DOM 中不存在,而非仅禁用。
6. **顶部条**:精简为 公告 / 实验 / 我的测试 / 数据资产 / 文档 + GitHub + 登录态;现有顶栏"运行台"按钮取消(运行台已并入实验模块)。

## 八、验收标准

1. 全站 HTML 页面数从 39 收敛到 ≤16,无 meta refresh 跳转残页,无死链。
2. 全站只有一个实验发起入口;匿名与所有者共用同一页面、按角色渲染。
3. 任何批次结果首屏包含:实验目的、模板版本、唯一自变量(或多变量标记)、固定条件摘要、`config_hash`、请求/生效对照、可见工具与 Schema 哈希。
4. 历史批次全部挂"旧实验定义";`baseline/full-system` 只以"整体实现方案诊断"出现,无"执行引擎单变量"表述。
5. `judging` 指标定义全站只有一份;`scoped` 不再被称为"全量工具"。
6. 空态只有"尚未发布 / 尚未运行"两种,无任何估算数字。
7. 游客可见的标题、按钮、表头、结果首行使用规范书面语(无口语比喻,也无未注解的开发者黑话);模板 ID、变量名、哈希只出现在技术口径行或折叠区,可逐页抽查。
8. 所有二级页面存在可见的返回上级入口,无导航死胡同。
