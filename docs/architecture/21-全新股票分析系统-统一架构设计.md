## 1. 架构结论

StockWise 采用“Python 统一编排、MCP 负责取数、分析能力负责计算”的架构。分析能力的最终部署形态后置决定。

```text
用户
  ↓
Python Agent / LangGraph
  ├── 问题理解
  ├── 数据需求规划
  ├── ReAct 工具决策
  ├── MCP / Java 数据调用
  ├── 数据标准化
  ├── 分析能力调用
  ├── 结果校验
  └── 最终回答与用户确认
       ↓
       ├── Market Data Gateway
       │     ├── akshare-one-mcp
       │     └── cn-financial-mcp
       ├── Java Portfolio Data API
       └── Python Analysis Engine（第一阶段默认实现）
             └── 可选：后续接入独立 Skill 服务
```

核心原则：

1. LangGraph 是业务流程控制器，不是数据源，也不是计算引擎；
2. Agent 只在需要动态决策的局部子图中运行；
3. MCP 只查询外部市场数据，不生成最终结论；
4. Java 只提供用户数据和账户数据，不负责 Python Agent 编排；
5. Skill 只基于输入数据分析、计算和总结，不执行查询；
6. 所有外部结果必须先转换成 Observation；
7. 所有 ReAct 都必须有预算、工具白名单和明确终止条件；
8. 所有长流程都必须支持 Checkpointer、`interrupt()` 和恢复执行。

## 2. 系统定位与范围

### 2.1 系统目标

系统面向完整的股票研究和交易辅助场景，支持：

- 标的识别和市场数据查询；
- 实时行情和历史行情分析；
- 技术面、基本面和估值分析；
- 行业、板块、资金流向和新闻分析；
- 用户持仓和账户影响分析；
- 策略设计和回测；
- 用户确认后的知识沉淀。

### 2.2 本阶段不建设

- 真实下单、撤单和改单；
- 券商交易执行；
- 让一个大 Agent 自由访问全部系统能力；
- Skill 内部查询市场数据；
- 无限循环 ReAct；
- 让大模型替代确定性指标、风险和回测计算；
- 通过 Java 继续承载新的 Agent 主流程。

### 2.3 新旧系统关系

Python 新系统独立开发，旧 Java 系统暂时保留并行运行：

```text
前端 / API Gateway
        ↓
Python LangGraph 新分析链路
        ├── MCP 市场数据
        ├── Java 用户数据
        └── 分析能力（第一阶段由 Python 提供）

旧 Java Agent 与 stock-wrapper 链路
        └── 代码保留仅作离线回归测试，不进运行时
```

迁移完成后，Java Agent 编排部分可以退役，但 Java 用户数据 API 是否保留，由后续业务迁移结果决定。

### 2.4 MCP 与 Skill 部署形态

两个 MCP 以远程 MCP 服务部署，Python LangGraph 通过 MCP Client 接入。两个服务的传输协议和端点必须通过配置区分，不得假设它们使用同一种 HTTP 传输方式。

分析能力暂不绑定 Node.js。第一阶段优先以 Python Domain/Analysis Engine 实现，跑通主流程后，再根据复用性、性能、依赖隔离和部署成本评估是否保留 Node Skill、改为独立服务或迁移为 Python 模块。`stock-wrapper` 不再属于新架构的运行时组件。

两个 MCP 必须分别配置传输方式、端点、认证、超时和连接池，不得假设两者使用同一种 HTTP 传输方式。推荐配置字段：`transport`、`endpoint`、`token`、`timeout_seconds`、`max_connections`。

云端部署可规避本机的系统代理与 TLS 指纹问题，但引入两个新约束：

- 本地 ↔ 云端的往返延迟（RTT）需计入 §10 的运行预算；
- 云服务器 IP 段可能被数据源风控（akshare 社区有已知反馈），**不假设 MCP 全量可用，以云端实测可达性为准**。

数据域风险分层（当前环境观察，必须通过云端部署重新验证）：

| 数据域 | 底层数据接口域名 | 风险等级 | 说明 |
|---|---|---|---|
| 财务报表、北向资金、宏观 | `datacenter-web.eastmoney.com` | 低 | 稳定，几乎不被风控 |
| 实时行情 | `push2.eastmoney.com` / `82.push2` | 高 | push2 系域名易被 TLS 指纹/IP 段风控 |
| 历史 K 线 | `push2his.eastmoney.com` | 高 | 同上，且存在间歇性失败 |
| 板块、个股资金流 | `17.push2.eastmoney.com` | 高 | 同上 |

因此 Phase 2 接入 MCP 后，首要工作是产出"能力 × 可用性"实测验证表，据此校准 §6.2 路由策略，而非直接信任 MCP README 声称的能力。

## 3. 组件职责

| 组件 | 技术形态 | 核心职责 | 禁止事项 |
|---|---|---|---|
| Python Application Runtime | Python | 配置、运行上下文、预算、错误、恢复 | 不直接写领域 SQL |
| Root Graph | LangGraph | 统一控制完整业务流程 | 不隐藏无限循环 |
| Query Graph | LangGraph | 理解用户问题和生成数据需求 | 不直接访问任意 MCP |
| Market Data Graph | LangGraph 子图 | 有界数据获取、降级和完整性判断 | 不生成最终投资结论 |
| Market Data Gateway | Python Service | 统一管理两个 MCP | 不让模型绕过路由表 |
| MCP Adapter | Python Adapter | 将 MCP 能力适配成内部 Tool | 不直接改变业务状态 |
| Java Data Adapter | Python Adapter | 调用持仓、账户和用户配置 API | 不负责市场数据查询 |
| Analysis Capability | Python Domain/Analysis Engine（第一阶段） | 基于输入数据分析、计算、领域总结；部署形态可替换 | 不查询外部数据 |
| StockWise Skill | 可选独立进程或服务 | 在需要时承载可复用的分析能力 | 不查询外部数据，不是主 Agent |
| stock-wrapper | 遗留 Node 服务 | 代码保留仅作离线回归测试，不进运行时 | 不得进入新生产链路，不作为数据备份源 |
| Domain Calculator | Python | 确定性指标、风险和校验计算 | 不依赖大模型结论 |
| Summary Model | Model Node | 将结构化结果组织成用户回答 | 不补造缺失事实 |
| Checkpointer | LangGraph Runtime | 保存线程状态和中断点 | 不保存未脱敏密钥 |
| Event / Trace | Runtime | 记录模型、工具、Skill 和节点执行 | 不记录明文敏感信息 |

## 4. LangGraph 执行模型

LangGraph 外层是整个业务流程控制器，类似状态机和工作流引擎。每个节点可以是：

```text
CODE                 普通确定性代码
TOOL_ONLY            只读工具调用
DIRECT_LLM           单次模型调用
STRUCTURED_LLM       结构化模型调用
BOUNDED_REACT_AGENT  有界 ReAct Agent
SUBGRAPH             LangGraph 子图
INTERRUPT            用户补充或确认
```

### 4.1 节点使用原则

- 数据校验、预算、状态变更使用 `CODE`；
- MCP、Java 和外部分析能力使用 `TOOL_ONLY` 或 Adapter；
- 问题理解和最终表达使用 `STRUCTURED_LLM` / `DIRECT_LLM`；
- 需要动态选择数据工具时使用 `BOUNDED_REACT_AGENT`；
- 复杂领域流程使用 `SUBGRAPH`；
- 缺少关键条件或需要用户批准时使用 `INTERRUPT`。

### 4.2 Root Graph

```text
receive_request
  ↓
understand_request
  ↓
check_missing_context
  ├── 缺少条件 → interrupt_for_clarification
  │                 ↓
  │             Command(resume=...)
  └── 条件完整
          ↓
build_data_requirements
          ↓
market_data_acquisition_graph
          ↓
load_portfolio_context（按需）
          ↓
assemble_analysis_input
          ↓
invoke_stockwise_skill
          ↓
validate_analysis_result
          ↓
compose_final_response
          ↓
user_confirmation（按需）
          ↓
finish
```

### 4.3 Market Data Graph

```text
build_query_plan
  ↓
select_next_data_action
  ↓
execute_market_tool
  ↓
normalize_observation
  ↓
evaluate_data_sufficiency
  ├── 完整 → end
  ├── 缺少数据 → select_next_data_action
  ├── 主源失败 → invoke_fallback_source
  ├── 数据冲突 → resolve_data_conflict
  └── 关键数据不可用 → LIMITED / interrupt
```

外层 Graph 必须负责 Tool 执行、Observation 追加、预算扣减、失败处理和终止判断。Agent 只输出一个结构化动作，不直接执行工具。

## 5. Agent 与 ReAct 设计

### 5.1 Query Agent

类型：`STRUCTURED_LLM`。

职责：

- 识别分析对象；
- 识别市场和标的；
- 识别时间范围；
- 识别分析类型；
- 判断是否涉及用户持仓；
- 判断是否需要用户补充条件。

Query Agent 不查询 MCP，不调用 Skill。

### 5.2 Research Agent

类型：`BOUNDED_REACT_AGENT`，只存在于 Market Data Graph。

每轮只返回一个动作：

```json
{
  "action": "get_historical_prices",
  "arguments": {
    "symbol": "600000",
    "period": "daily",
    "lookback_days": 120
  },
  "reason": "技术分析需要历史价格序列"
}
```

允许调用的工具仅包括只读数据工具，禁止：

- 下单、撤单和交易执行；
- 写数据库；
- 修改用户持仓；
- 调用未注册 MCP；
- 调用 Skill 进行下一轮查询；
- 无限循环或自行延长预算。

### 5.3 Summary Model

类型：`DIRECT_LLM`。

只读取：

- 标准化 Observation；
- 分析能力返回的 `AnalysisResult`；
- 数据质量和限制；
- 用户已确认的上下文。

Summary Model 不得补造实时价格、财务数据、新闻事实或未提供的持仓数据。

### 5.4 ReAct 执行矩阵

- `market_snapshot`：确定性快路径，不启动 Agent/ReAct；
- `technical`、`fundamental`、`valuation`：固定数据计划优先，缺失字段、分页或主源失败时允许有限自适应；
- `portfolio_impact`：用户数据或市场数据依赖不完整时允许有限 ReAct；
- `comprehensive`：允许完整但有界的 ReAct。

只有 `comprehensive` 使用完整 ReAct；其他分析类型的 ReAct 轮数是上限，不代表每次都会启动 Agent。

## 6. MCP 市场数据架构

### 6.1 MCP 定位

MCP 是外部数据能力接入协议，不是系统的核心计算引擎。Python 启动时通过 Adapter 建立 MCP Client，并转换为受控的内部 Tool。两个 MCP 的传输协议和端点必须分别配置，不能假设它们使用同一种 HTTP 方式。

```text
MCP Server
  ↓
MCP Client / Adapter
  ↓
Market Data Gateway
  ↓
统一内部 Tool
  ↓
Market Data Graph / Agent
```

### 6.2 两个 MCP 的统一策略

`akshare-one-mcp` 和 `cn-financial-mcp` 的能力存在重叠，不能把两个服务的同类工具全部直接暴露给模型。

统一能力名称：

```text
market.resolve_instrument
market.get_realtime_quote
market.get_historical_prices
market.get_financial_statements
market.get_valuation
market.get_industry_context
market.get_money_flow
market.get_news
```

交易日历不作为 MCP 能力暴露，由 Python `domain/` 层通过 `TradingCalendarProvider` 统一提供。若本地日历无法覆盖真实交易日规则，应接入独立交易日历数据源，不能让 Skill 或 MCP 查询逻辑隐式补充。

初始路由（云端部署后的默认值，Phase 2 必须用"能力 × 可用性"实测结果校准）：

| 统一能力 | 默认源 | 异构备份 | 数据域风险 |
|---|---|---|---|
| 标的搜索 | `cn-financial-mcp` | — | 低 |
| 实时行情 | `cn-financial-mcp` | `akshare-one-mcp`（同源，非真正备份） | 高（push2 系） |
| 原始历史 K 线 | `cn-financial-mcp`（禁用其指标参数） | `akshare-one-mcp`（同样禁用指标） | 高（push2his） |
| 财务报表 | `cn-financial-mcp` | `akshare-one-mcp` | 低（datacenter，稳定） |
| 估值、行业、资金流 | `cn-financial-mcp` | — | 中 |
| 新闻和公告 | `cn-financial-mcp` | `akshare-one-mcp` | 低 |

三条强制约束：

1. **同源不构成高可用备份**。两个 MCP 均基于 akshare，数据源、fallback 链和被风控方式可能相同——主源挂时备源可能同时挂。两个 MCP 连续失败时，`MarketDataGateway` 必须返回结构化失败或 `LIMITED`，**不得调用 Skill 补查数据**。`stock-wrapper` 和旧 `/api/v1/*` 不作为备份源。后续如需真正异构备份，应接入独立的第三方市场数据服务（如腾讯 `web.ifzq.gtimg.cn`），并通过新 Adapter 接入；是否接入，由 Phase 2 实测验证结果决定（见 §10.2 逃生阀）。
2. **两个 MCP 不能同时作为同一字段的并行默认源**。只有在数据校验或冲突分析场景下，才允许主动调用第二数据源。
3. **`akshare-one-mcp` 的历史 K 线不是纯原始数据**。它的 `get_hist_data` 会在取数时计算 SMA/MACD/RSI/BOLL 等指标（`indicators_list` 参数）。调用时**必须显式传空 indicators**，且其预计算指标最多作为校验数据，不得作为默认最终结论（与 §8.3 计算责任一致）。

主备路由必须配置化。第二数据源只用于：主数据源失败、关键字段校验、数据冲突比对、明确要求多源对照。

### 6.3 MCP 调用记录

每次调用必须记录：

- MCP 名称；
- 统一 Tool 名称；
- 原始 Tool 名称；
- 请求参数；
- 请求时间；
- 数据时间；
- 响应耗时；
- 是否使用备用源；
- 是否发生数据冲突；
- 原始响应引用。

## 7. Java 用户数据架构

Java 不再负责新的 Agent 主流程，但继续作为用户数据服务提供方：

```text
portfolio.get_current_positions
portfolio.get_account_snapshot
portfolio.get_transaction_history
user.get_risk_profile
```

调用链：

```text
Python Tool Adapter
  ↓
Java HTTP API
  ↓
用户数据 DTO
  ↓
Observation Normalizer
  ↓
Portfolio / Analysis State
```

Java 返回的数据必须包含用户授权范围、数据时间和查询状态。Python 不允许绕过 Java API 直接读取用户业务表。

## 8. 分析能力架构（可选 Skill）

### 8.1 分析能力定位

分析能力只消费已经标准化的 `AnalysisInput`，完成指标计算、风险判断和领域分析，不是主 Agent，也不是查询服务。第一阶段默认由 Python Analysis Engine 实现；是否继续使用现有 Node Skill，待主流程跑通后单独评估。

```text
Python 组装 AnalysisInput
  ↓
 AnalysisCapabilityAdapter
  ↓
 Python Analysis Engine
  ↓
AnalysisResult
```

未来若评估决定把分析能力独立部署为服务，可沿用以下兼容接口；当前不要求实现：

```text
GET  /health
GET  /ready
POST /api/v2/analyze
```

现有 `stock-wrapper` 和 `/api/v1/*` 分析接口不进入新生产链路，也不作为数据备份源。若保留旧 CLI 或 Node Skill，只允许使用固定 fixture/replay 数据做离线回归，不得依赖真实行情接口。

分析能力禁止：

- 查询 MCP；
- 查询 Java；
- 查询数据库；
- 访问行情接口；
- 根据股票代码自行补充数据；
- 启动内部 ReAct；
- 决定下一步数据工具。

### 8.2 分析能力契约

第一阶段调用形式：

```python
result = analysis_capability.analyze(analysis_input)
```

`AnalysisCapabilityAdapter` 负责屏蔽本地函数、子进程或未来 HTTP 服务的差异，LangGraph 节点不得硬编码具体通信方式。

未来独立服务可以兼容：

```http
POST /api/v2/analyze
Content-Type: application/json
```

```python
class AnalysisInput(BaseModel):
    schema_version: str
    analysis_id: str
    analysis_type: str
    instrument: InstrumentRef
    realtime_quote: RealtimeQuote | None
    historical_prices: list[HistoricalBar]
    financial_data: FinancialBundle | None
    valuation_data: ValuationBundle | None
    industry_context: IndustryContext | None
    news_context: list[NewsItem]
    portfolio_context: PortfolioContext | None
    overseas_context: OverseasContext | None
    data_quality: DataQuality
    provenance: list[ProvenanceRecord]
    methodology_version: str
```

核心数据块必须包含 `as_of`、`source`、`retrieved_at` 和 `quality_status`。财报分页必须携带 `page_token`、`page_size`、`source_request_id`，恢复时不得重复写入已完成页。

核心类型的最低字段要求：`InstrumentRef` 包含 `symbol`、`name`、`market`、`exchange`、`instrument_type`；`DataQuality` 包含 `completeness`、`freshness`、`quality_status`、`known_unavailable`；`ProvenanceRecord` 包含 `source`、`tool`、`request_id`、`as_of`、`retrieved_at`、`fallback_used`。

分析类型：

```text
market_snapshot
technical
fundamental
valuation
portfolio_impact
comprehensive
```

```python
class AnalysisResult(BaseModel):
    schema_version: str
    analysis_id: str
    status: str
    facts: list
    calculated_indicators: dict
    signals: list
    risk_flags: list
    conclusions: list
    limitations: list
    data_quality: DataQuality
    provenance: list
    methodology_version: str
```

状态：

```text
SUCCESS / PARTIAL / LIMITED / FAILED
```

### 8.3 计算责任

MCP 默认返回原始行情、财务和新闻数据，Skill 或 Python Domain 层完成：

```text
OHLCV
  → MA / EMA / MACD / RSI / ATR
  → 波动率 / 最大回撤 / 支撑阻力
  → 技术信号 / 风险标记 / 分析结论
```

必须记录指标参数、复权方式、时间范围、算法版本，并防止未来函数。MCP 预计算指标最多用于校验，不作为默认最终结论。

## 9. 统一数据模型

## 10. 运行预算、错误和中断

默认运行预算（按 `analysis_type` 分档，云端 MCP 调用需叠加往返延迟）：

| analysis_type | ReAct 轮数上限 | Tool 调用上限 | 子图预算 | 总请求预算 |
|---|---|---|---|---|
| `market_snapshot` | 2 | 3 | 25s | 40s |
| `technical` | 4 | 5 | 45s | 70s |
| `fundamental` | 5 | 7 | 55s | 90s |
| `valuation` | 4 | 5 | 45s | 70s |
| `portfolio_impact` | 6 | 8 | 60s | 100s |
| `comprehensive` | 10 | 14 | 150s | 240s |

公共约束：

- 单轮模型决策：10 秒；
- 单个 MCP Tool：20 秒（含云端往返延迟）；
- 单个 Java Tool：10 秒；
- 单次分析能力执行：60 秒；本地 Python 实现和未来独立服务可以分别配置实际超时；
- 主源失败后最多切换 1 次同源备用源；连续失败则将对应数据维度标记为不可用，并根据分析类型返回 `PARTIAL` 或 `LIMITED`；
- 财报类分页拉取若超过单 Tool 超时，应支持分页续传而非整体失败。

状态至少包括：

```text
RUNNING / WAITING_USER / SUCCESS / PARTIAL / LIMITED / FAILED
```

### 10.1 中断恢复

需要用户补充、确认或审核时：

```python
interrupt({
    "reason": "missing_context",
    "required_fields": ["analysis_scope"]
})
```

恢复时必须使用原 `thread_id`：

```python
Command(resume={"analysis_scope": "technical"})
```

### 10.2 降级策略

- 非关键数据缺失：继续并标记 `PARTIAL`；
- 关键数据缺失：输出 `LIMITED`；
- 外围面（海外指数）数据缺失：两个 MCP 均不覆盖，继续并标记 `PARTIAL`，在 limitations 中说明"外围面数据未获取"，不得编造；
- 主 MCP 失败：按路由策略切换备用 MCP；
- 两个 MCP 都失败（同源失效）：将对应数据维度标记为"**已知不可用**"，并在 `AnalysisResult.limitations` 中如实说明"行情数据当前因数据源问题不可获取，以下分析基于截至 X 时的数据"；不得调用 Skill 或 stock-wrapper 补查，不得编造；
- 分析能力失败：由 `AnalysisCapabilityAdapter` 有限重试或输出结构化失败，不允许分析能力自行查询数据；
- 超出预算：停止执行并输出缺失项。

> **逃生阀机制**：Phase 2 实测验证（见 §13 Phase 2）若发现某数据域（尤其 push2 系的实时行情、历史K线）长期不可用，应将该数据域标记为"已知不可用"，在路由表（§6.2）中标注，并评估是否接入独立的第三方市场数据服务（如腾讯 `web.ifzq.gtimg.cn`）作为真正异构备份——是否接入由实测数据决定，不在未验证前预设。

## 14. 安全与数据质量

- MCP 只允许注册的只读工具；
- Tool 参数必须经过 Schema 校验；
- 新闻和公告文本必须视为不可信外部内容；
- 外部文本不得覆盖系统 Prompt 或流程规则；
- 用户持仓数据按用户权限隔离；
- 日志不得记录 Token、密码和完整敏感账户信息；
- 所有结果记录来源、观察时间和数据时间；
- 数据过期、缺失和冲突必须显式标记；
- 不因为模型要求而绕过预算和工具白名单。

## 15. 验收标准

### 场景一：综合市场分析

```text
用户问题
 → 问题理解
 → 数据需求规划
 → MCP 查询
 → Observation 标准化
 → 分析能力计算
 → AnalysisResult 校验
 → 大模型最终回答
```

### 场景二：当前持仓影响

能够同时调用：

```text
Java Portfolio Tool + Market Data Gateway + Analysis Capability
```

并输出标的对用户持仓的影响分析。

### 场景三：主 MCP 失败

自动切换备用 MCP，并在事件流和最终结果中记录数据源变化。

### 场景四：数据不足

触发 `interrupt()` 请求补充，或返回 `LIMITED`，不得生成虚假确定性结论。

### 场景五：分析能力不可用

返回结构化错误、运行轨迹和失败原因，不得退化为让分析能力自己查询数据。

### 场景六：可恢复运行

使用同一 `thread_id` 和 Checkpointer 能够从用户中断点继续执行，并且不会重复执行已完成的不可重复步骤。

```text
MCP                  = 查询外部市场数据

Python LangGraph     = 统一 Agent 和业务流程
Analysis Capability  = 纯分析、纯计算、纯总结
LLM                  = 理解、决策、解释和最终表达
```
