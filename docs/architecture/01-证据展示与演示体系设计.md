# 证据展示与演示体系设计

> 状态：设计定稿，待实施
> 日期：2026-08-20
> 从属：本文件从属于 [00-Sentinel产品设计与架构.md](./00-Sentinel产品设计与架构.md) §7（前端规格）、§8（演示验收场景）、§11.2（eval 对照）；不修改 P1–P6 既有职责，只新增公开展示区与演示支撑层。

## 1. 定位与范围

本项目是面试展示项目，核心资产不是聊天界面，而是**可验证的工程证据**：A/B 对照数字、单次运行的完整链路轨迹、失败与拦截样本。本设计定义三件事：

1. **公开只读展示区**（`/showcase`）：只渲染真实运行产出的工件，零交互、零输入、零后端依赖；
2. **登录演示模式**：面试当场由本人驾驶真实系统（§8 六步看护主线 + 固定分析用例台）；
3. **录屏兜底**：现场故障时无缝切换到工件回放继续讲述。

非目标：公开访客自助试用、公开区触发真实 LLM、任何形式的演示数据手写。

## 2. 总体结构

```text
工件生成（真实运行的副产物，不可手写）
  ├─ ab_eval --export-traces     每次评测落 trace 工件 + ab_report.json
  ├─ 演示捕获（demo 档）           lab / §8 七步运行落 trace 工件
  └─ live 运行                    /runs/{id}（P6，按需生成同格式）
        ↓ 统一 TraceArtifact JSON
展示层（公开只读，纯静态）
  ├─ /showcase            定位页：一句话定位 + 链路图 + 原则
  ├─ /showcase/eval       评测报告页（A/B 总表、口径、实验设置）
  ├─ /showcase/ab         失败对照页（baseline 失败 vs treatment 成功，并排）
  └─ /showcase/traces     trace 回放页（列表 → 单条逐步回放）
演示层（登录后）
  ├─ 轨 A：§8 六步看护主线（rehearse 脚本全绿为门禁）
  └─ 轨 B：固定分析用例台（预设用例点选，含拦截演示用例）
```

三层共用一个事实：**展示的每个字节都来自真实运行工件，工件生成即冻结**。

## 3. TraceArtifact 统一格式

三种来源（eval / 演示捕获 / live）落同一 schema，同一 viewer 渲染，不维护第二份展示数据结构。

```json
{
  "artifact_version": 1,
  "trace_id": "ab-research-01-r3-treatment",
  "source": "ab_eval | demo_capture | live_run",
  "group": "baseline | treatment | null",
  "case_id": "research-01",
  "created_at": "2026-08-20T14:03:00+08:00",
  "run_context": {
    "model": "glm-4.7-flash", "temperature": 0.1,
    "tool_loading": "scoped", "scene_tag": "market",
    "authenticated": false, "fastpath_expected": null
  },
  "entry": { "message": "宁德时代现在什么价", "fastpath": null, "entered_loop": true },
  "loaded_tools": ["market.get_realtime_quote", "market.get_historical_prices"],
  "steps": [
    { "seq": 1, "kind": "llm", "tokens_in": 812, "tokens_out": 45, "latency_ms": 830,
      "decision": "CALL_TOOL", "prompt_ref": "scene_chat" },
    { "seq": 2, "kind": "tool", "name": "market.get_realtime_quote",
      "args_digest": { "symbol": "300750" }, "status": "SUCCESS",
      "audit_code": "RO-OK", "latency_ms": 210,
      "observation_digest": { "price": 218.30, "as_of": "2026-08-19" },
      "quality_flags": ["DQ-FRESH"] }
  ],
  "guardrail": { "output_fixes": [ { "check": "number_grounding", "before": "…", "after": "…" } ] },
  "outcome": { "final_status": "COMPLETE | REFUSED | DEGRADED", "answer_excerpt": "…", "citations": 2 },
  "judgment": { "tool_correct": true, "number_hallucinations": [], "c1": [], "c2": [], "forbidden_leak": [] },
  "metrics": { "llm_rounds": 2, "prompt_tokens": 1200, "completion_tokens": 180,
               "tool_calls": 1, "duration_ms": 2100 }
}
```

规则：

- **digest 不存全量**：Observation 与工具参数存摘要（关键字段截断），防敏感数据与体积膨胀；回放页展开的也是摘要，证据链完整性由审计码 + 引用编号表达。
- `judgment` 仅 eval 来源携带；`group` 仅 A/B 来源携带。
- `prompt_ref` 指向 `sentinel-engine/prompts/` 场景文件名，不内联提示词全文。
- 工件不可变：落盘后任何展示层与脚本不得改写、挑选、删改（失败工件同样保留）。

## 4. 工件生成

| 来源 | 触发 | 落盘位置 |
|---|---|---|
| A/B 评测 | `ab_eval --export-traces DIR`（既有 runner 加导出开关），每 case × 每组 × 每次运行各一件；同时落 `ab_report.json`（ABReport 机器可读版，失败对照页数据源） | `docs/eval/artifacts/` |
| 演示捕获 | demo 档下 lab 用例与 §8 七步的运行结束钩子，把 AgentResult + 判官产物序列化同格式 | `docs/eval/artifacts/`（`source=demo_capture`） |
| live 运行 | P6 `/runs/{id}` 请求时按 schema 组装返回，不落公开工件 | 内存 / 运行存储 |

构建展示区时由脚本把 `docs/eval/artifacts/` 与最新报告同步进 console 静态目录（单向拷贝，展示区不是第二份真源）。

## 5. 展示层页面规格（公开只读区）

路由前缀 `/showcase`，全部纯静态、无按钮、无输入、不调后端；视觉沿用 §7.2 徽标体系（审计码徽标、证据引用编号、演示水印）。

### 5.1 定位页 `/showcase`

- 一句话定位 + 链路图（事件源 → 唤醒 → 上下文组装 → 循环 + 治理中间件 → 通知），标注「模型提议，代码裁决」；
- 三张入口卡片：评测报告 / 失败对照 / trace 回放，各带一行说明；
- 页脚固定工件生成时间戳与「数据全部来自真实运行工件」声明。

### 5.2 评测报告页 `/showcase/eval`

- 渲染最新一份（可列出历史）`设计模式有效性对照`：实验设置（模型、温度、题量、判官口径）→ 总表 → 模式归因 → 分场景表；
- 数据源为 `ab_report.json`，页面渲染，不手贴 markdown。

### 5.3 失败对照页 `/showcase/ab`

- 从 `ab_report.json` 自动挑选「baseline 失败且 treatment 成功」的 case，每条并排两列：输入 → 工具轨迹步骤条 → 答案摘录 → 违规审计码；
- 左列（baseline）的幻觉工具、越权调用、数字幻觉直接用徽标标出，右列（treatment）展示拦截点（G1–G7 审计码、Output Guardrail 修正）；
- 无合格样例时页面显示「本期无」，不造样例。

### 5.4 trace 回放页 `/showcase/traces`

- 列表视图：按 case / 组（baseline·treatment）/ 场景过滤（过滤是视图行为，不是交互输入）；
- 详情视图：头部固定展示受控变量（模型、温度、装载策略、场景、认证态），主体为步骤条回放——LLM 轮（token/时延/决策）、工具卡（名称、参数摘要、审计码、观察质量标记）、guardrail 修正、结局与判官结论；
- 演示捕获来源的工件整页带 §7.2 演示水印。

## 6. 演示模式（登录后由本人驾驶）

### 6.1 双轨演示脚本

| 轨 | 内容 | 兜底特性 |
|---|---|---|
| A：看护主线 | §8 六步：首页 → 注入 −5.2% 事件 → 通知解读（证据链 + 审计码）→ 运行回放 → 分析用例（估值 / 风险匹配筛查 DRAFT）→ 拦截用例（只读红线 + 审计码） | 注入驱动，零真实市场依赖；`demo-rehearse.ps1` 全绿才允许上场 |
| B：能力纵深 | 固定分析用例台按场景过一遍预设用例（行情 / 估值 / 组合 / 适合度 DRAFT / 拦截演示） | 预设台词 + 真实循环，无自由输入，演示结果可控 |

### 6.2 环境与边界

- 演示环境为本地全栈（compose + LLM key），不暴露公网；公网只发布 `/showcase` 静态区；
- 既有 dashboard / 分析用例台（lab）页面维持各自登录边界，不在公开区镜像任何可触发 LLM 的入口。

## 7. 录屏兜底

`recordings/`（不入库，本地归档）约定固定三份，每份文件名旁配一行元信息（日期、模型、commit）：

```text
recordings/demo-main.mp4          §8 六步全程（3–5 分钟）
recordings/demo-lab.mp4           固定分析用例台预设用例全程（含拦截演示用例）
recordings/showcase-walkthrough.mp4  trace 回放页讲解（旁白讲链路）
```

现场任何一步失败：立即切 `/showcase/traces` 对应工件或录屏继续讲述，不重试、不冷场。

## 8. 与真源文档的关系

- 本设计实施时在 00 号文档 §7.1 页面清单补登 showcase 区（P7），并在 §14 变更记录登记；当前先不动真源，获批后随首个实施切片一起回填；
- P6 `/runs/{id}` 的数据结构按本文件 §3 对齐，实现先后不限，不互相阻塞；
- 评测题库与判官口径仍以 `tests/eval/ab_eval.py` 与 §11.2 为准，本设计只消费其产物。

## 9. 实施顺序

1. TraceArtifact schema 落为 `tests/eval/trace_artifact.py` + `ab_eval --export-traces`，既有 15 题跑一遍产出首批工件与 `ab_report.json`；
2. console 新增 `/showcase` 静态区骨架：定位页 + trace 列表/详情回放；
3. 评测报告页 + 失败对照页（消费 `ab_report.json`）；
4. 演示捕获钩子（demo 档落 `source=demo_capture` 工件）+ recordings 三份录屏 + rehearse 门禁输出对齐展示口径；
5. P6 live 回放按 §3 对齐（随 00 号实施路线走）。

## 10. 明确禁止

- showcase 区出现任何可交互输入、按钮或可触发真实 LLM 的入口；
- 手写、编辑、挑选性删改 trace 工件与报告数据；失败工件必须原样保留；
- 展示层维护第二份结果数据（只读工件，单向同步）；
- 公开区出现未 digest 的用户数据、持仓真实样本或密钥类配置；
- 以「演示数据」名义绕过 C-4 演示水印体系。
