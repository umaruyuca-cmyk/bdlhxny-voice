## 3. 核心机制 → 实现（设计文档 §4）

### 3.1 统一工具模型（§4.1）

| 设计要求 | 实现 |
|---|---|
| ToolCard 七字段唯一真源 | `tools/catalog.py`：`ToolCard`（name/description/parameters/origin/read_only/required_scope/cost_hint）、`ToolCatalog`（重名 / 交易语义 / 只读三关，`is_trading_semantic` 承载 C-1）、`catalog_from_snapshot()` 从数据库 Registry 快照构建 |
| MCP 工具代理登记 | `integrations/mcp/registry.py` + `integrations/mcp/adapter.py`（`origin=mcp`）；动态登记 `register_mcp_tool` |
| Registry 数据库真源 | Python 侧 `registry/`（`load_and_validate`）+ Java `api/RegistryController.java`；DDL：`db/postgresql/schema/registry.sql`；种子：`db/postgresql/seed/registry.sql` |

### 3.2 工具装载（§4.2）

| 设计要求 | 实现 |
|---|---|
| scoped 场景映射 | `engine/loader.py`：`SCENE_TOOLSETS`（market/portfolio/research/watch → scope 集）、`load_scoped()`（`list_visible` 任一 scope 命中 + 游客过滤） |
| search 检索装载 | `engine/loader.py`（`load_for_turn` / `run_search` / 连续未命中回退 `research` 宽包）+ `tools/search.py`（`ToolSearchIndex`，Qwen embedding 余弦 top-k，阈值 0.28，`EncoderUnavailableError` 降级）；元工具 `search_tools` 登记于 `tools/catalog.py` |
| 权限先于检索 | `run_search` 对 `load_scoped` 结果检索（索引不含无权工具） |
| 配置 | `config.py`：`BDLH_TOOL_LOADING=scoped|search`（默认 scoped） |

测试：`tests/engine/test_search_loading.py`（命中 / 回退 / 缓存 / 预算）、`tests/tools/test_search.py`。

### 3.3 Agent 循环（§4.3 三层闸门）

| 闸门 | 实现 |
|---|---|
| G-α 快路径 | `engine/semantic_router/`：`engine/semantic_router/router.py`（chitchat / knowledge / forbidden 分流）+ `engine/semantic_router/fastpath_data.py`（样句）+ `engine/semantic_router/encoder.py`（Qwen embedding）；入口在 `engine/loop.py` `AgentLoop.run()` |
| G-β 模型自主直答 | `engine/loop.py`：无 `tool_calls` 即直答；每轮 `bind_tools(load_for_turn(...))` 重绑 |
| G-γ 预算上限 | `guardrails/middleware.py`（G4）+ `AgentLoop(max_tool_calls)` |
| 类型化结果 | `contracts/observation.py`（`result_type` + `payload`）→ `api/projections.py` `chat_final_payload()` 投影 blocks，数字不经 LLM 转述 |

执行装配：`engine/runtime.py`（`EngineRuntime`）+ `engine/executor.py`（`CatalogToolExecutor`）；提示词文件化：`prompts/system_base.md`、`prompts/scene_chat.md`、`prompts/scene_direct.md`、`prompts/scene_wakeup.md`（禁止内联长字符串）。测试：`tests/engine/test_loop.py`。

### 3.4 治理中间件（§4.4 G1–G7）

`guardrails/middleware.py`：`GovernanceMiddleware.invoke()` 固定链 G1 可见性 → G2 只读 → G3 权限（scope 取自 `loader.granted_scopes`）→ G4 预算（premium ×3）→ G5 pydantic 参数校验 → 执行 → G6 Observation 包装（复用 `guardrails/data_quality_rules.py`）→ G7 `AuditRecord`。本地与 MCP 同一链。测试：`tests/guardrails/test_middleware.py`（16 例逐条拦截）。

输出侧护栏（设计 §4.3 展示真源的延伸）：`engine/output_guardrail.py`（`OutputGuardrail`：`NumberGroundingCheck` 数字接地、`C1ComplianceCheck` / `C2ComplianceCheck` 合规复核）。

### 3.5 上下文组装（§4.5）

| 通道 | 实现 |
|---|---|
| 唤醒态 | `watch/wakeup.py`（`WakeupAssembler`，端口 `PortfolioSnapshotProvider` / `RiskProfileProvider` 经 `infra/remote_runtime_data.py` 取数；L3 召回 `memory/recall.py`） |
| 用例态 | `engine/loop.py`（系统提示 + 用例输入 + L3 记忆注入 `AgentTurn.memory_records`；历史轮数 `BDLH_SESSION_HISTORY_TURNS`） |

### 3.6 记忆子系统 L3（§4.7）

| 环节 | 实现 |
|---|---|
| 召回 | `memory/recall.py`（`recall_semantic_memory`）→ `memory/remote.py`（remote 客户端，`BDLH_MEMORY_MODE`） |
| 写入 | `memory/writer.py`（候选经 Java `api/MemoryCandidateController.java` 确认入库） |

| 降级 | 召回失败标记 `memory_degraded`，`infra/readiness.py` `/ready` 显性上报 |

### 3.7 事件驱动子系统（§4.8）

| 设计要求 | 实现 |
