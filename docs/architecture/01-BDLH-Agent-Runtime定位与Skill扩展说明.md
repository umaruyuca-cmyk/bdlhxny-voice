## 1. 一句话定位

BDLH Agent Runtime 是一个**通用 Agent Runtime / 编排内核**：它把「理解意图 → 选择行动 → 调度领域 → 受控调用外部能力 → 标准化观察 → 确定性计算 → 治理后表达」这条链固定下来，并让具体业务以 Skill 形式挂载。

金融是挂在这个内核上的**第一个 Domain（业务领域）**；股票客观研究、组合健康和用户适配性评估属于该领域内的 Skill，不是内核本身。

本文中需要区分三个层次：

- **Core Runtime / Cognitive Kernel（核心运行时 / 认知内核）**：与业务领域无关，负责认知编排、领域调度、能力网关、观察标准化、治理和生产持久化；
- **Domain Runtime（领域运行时）**：某个领域的 Skill 宿主，负责领域请求校验、Skill 选择、能力授权求交和领域结果组装；
- **Skill（业务技能）**：某个领域内可独立声明、注册和测试的业务能力。

当前只有 `finance` Domain Runtime；它是 Core Runtime 通过 Domain Dispatcher 调度的第一个领域实例，不等于整个 BDLH Agent Runtime Runtime。

## 2. 内核解决的是什么问题

让大模型参与生产系统时，真正难的不是让它「能回答」，而是让它的输出**可追溯、可降级、可审计、可复现**。内核就是这套约束的载体：

| 内核关注点 | 具体做法 |
|---|---|
| 模型不能直接碰工具 | 认知层只输出结构化行动，能力调用统一经 Capability Registry 与 Adapter |
| 外部数据不能直接变结论 | 所有外部响应先转 Observation，携带来源、时间、质量与降级状态 |
| 确定性计算不能交给模型 | 指标、风险、估值、规则判定在纯计算模块完成，固定输入得固定输出 |
| 不确定必须显式 | 结果状态区分 `COMPLETE / PARTIAL / LIMITED / FAILED`，禁止把有限结果包装成确定结论 |
| 数据真实性不能被伪装 | `LIVE / USER_CONFIRMED / TEST_FIXTURE / MOCK / UNAVAILABLE` 分级，测试数据不得进入真实结论 |
| 每一步都要能被拦下来 | 四时点治理：规划时、行动时、数据返回时、表达前 |
| 记忆不是账本 | 记忆分五层，业务真源独立于记忆，且记忆不能自行晋升为真源 |
| 失败要可预期 | 依赖分级、预算与截止时间、幂等键、结构化错误、可回滚的迁移 |

这些关注点不含任何金融语义，因此更换业务领域时不需要重写。

## 3. 分层与扩展点

分层正文见 00 号文档 §1 与 §5，这里只说扩展点落在哪里：

| 想加的东西 | 挂在哪 | 需要写什么 |
|---|---|---|
| 同领域的新业务能力 | 现有 Domain Runtime 内新增 Skill | 一份 `SkillManifest` + 业务实现 |
| 一个全新业务领域 | 注册新 Domain 到 Dispatcher | `DomainDescriptor` + Skill + 该领域的确定性计算模块 |
| 检索增强（RAG） | 某领域下的检索类 Skill | 检索结果转 Observation 后作为证据候选 |
| 多角色协作 | 认知层内部的角色子图 | 角色声明与预算切分，不新增部署单元 |

四条边界（对应 ADR-009、ADR-010、ADR-012）：

1. 认知层与领域调度层不依赖任何具体领域的枚举、契约或计算模块，由一条常绿的 import 测试保证；
2. Skill 是编译期注册的一等对象，启动时对能力真源逐项校验，不一致即启动失败；
3. 新增 Skill、Domain 或角色只允许注册与复用，不允许复制能力真源、观察层、治理层、预算模型或审计链；
4. 多 Agent 的价值来自隔离，不是角色扮演；无隔离需求时用子图实现。

## 4. 金融 Skill 的位置

金融领域当前已声明三个 Skill：客观股票研究、组合健康、适配性评估。其中只有 `stock-research` 已进入可运行状态，`portfolio-health` 和 `suitability-evaluation` 仍属于 `FOUNDATION`，尚未进入默认生产路径。两条领域内的硬性约束值得单独提及，因为它们是「用 Agent 做严肃业务」的典型代价：

- **客观研究与用户适配性分离。** 「这只股票怎么样」和「这只股票适合你吗」是两个不同的产出：前者只描述资产，后者必须结合权威用户事实并由确定性规则判定。研究结论中不允许出现「适合你」。
- **缺数据时给不出结论，而不是给一个看起来合理的结论。** 缺风险画像、缺持仓行情、数据来源是测试或模拟态时，结果固定为「信息不足」，不允许用默认值、成本价或过期行情凑出个性化判断。

对外金融能力全程只读：不下单、不调仓、不转账。用户资料的写入与确认走独立认证接口，不是 Agent 能调用的能力。

## 5. 术语与目录对照

代码目录名保留了历史演进痕迹，阅读时按下表对照（目录收敛按 00 号文档 §7 延后处理，不影响逻辑边界）：

| 逻辑概念 | 当前目录 | 备注 |
|---|---|---|
| 认知内核 | `cognitive/` | 只依赖通用领域契约 |
| 领域调度 | `domains/registry.py`、`domains/contracts.py` | Dispatcher 与跨层契约 |
| 领域实现（Skill 宿主） | `domains/finance/` | 当前唯一领域 |
| 确定性计算 | `domain/` | 与 `domains/` 是两个不同层，名称相近属历史遗留 |
| 能力真源与网关 | `tools/` | Registry 唯一真源，Toolset 为派生视图 |
| 供应商适配 | `integrations/` | 隔离协议与凭证 |
| 观察标准化 | `observations/`、`contracts/observation.py` | 统一来源、质量、时间与错误 |
| 治理 | `guardrails/` | 四时点 |
| 装配与持久化 | `runtime/`、`runtimes/` | 前者是应用装配，后者是编排实现 |
