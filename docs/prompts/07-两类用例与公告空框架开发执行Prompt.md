四、统一领域模型和运行数量

在后端、前端、数据库设计和公开工件中统一：

1. `test_type` 只有：
   - `COMPRESSION_CASE`：压缩用例；
   - `COMPARISON_CASE`：对比用例。
2. `agent_mode_id` 表示三种 Agent 实现，不用页面显示名称作为业务判断条件。
3. `repeat_count` 表示相同实验条件创建多少个独立运行：
   - 压缩用例每个 4×3 单元固定为 1；
   - 对比用例只能为 3 或 5，前后端都要校验。
4. `max_agent_steps` 表示单次 Agent 运行中模型判断和工具结果回传的最大步数：
   - 与 `repeat_count` 分开保存、显示和校验；
   - 达到上限时保存已有证据并记录 `stop_reason=MAX_AGENT_STEPS`；
   - 得到最终回答后立即停止，不为了达到上限继续调用。
5. 运行前准确计算并显示：
   - 一个压缩 Session 完整 4×3 为 12 个运行；
   - 三个压缩 Session 全部运行理论上为 36 个，但页面不得提供默认连续执行三个 Session 的按钮；
   - 一个对比用例重复 3 次为 9 个运行；
   - 一个对比用例重复 5 次为 15 个运行。

不要继续保留会让调用方自由组合成其他运行数量的旧参数。为了兼容已有内部代码确实需要旧枚举时，增加明确的转换层和弃用说明，公开接口只使用新口径。

五、实现压缩用例模块

1. 数据来源只允许上下文压缩模块维护的三个版本化长 Session：
   - 产品演进与需求决策；
   - 上下文引擎排查；
   - 数据库与部署。
2. 从普通用例库和公开对比用例 JSON 中移除旧 `ctx-*` 长上下文用例，不复制一份 Session 到用例库。
3. 每次选择一个 Session，冻结 `session_id`、`session_version`、`current_event_id`、当前消息哈希、历史哈希、工具目录版本、Mock 数据版本、模型条件、算法版本和 Token 预算。
4. `current_event_id` 对应的最新有效用户消息只作为当前输入发送一次；其之前的事件作为历史。禁止当前问题同时进入历史压缩和当前输入。
5. 支持四种上下文方式：
   - `full-session`：完整对照；
   - `recent-window`：最近窗口基准；
   - `single-summary`：一次摘要基准；
   - `budgeted-session`：本项目按预算压缩算法。
6. 四种方式都经过相同的输入构建、Token 统计、校验和工件冻结，但只有 `budgeted-session` 可以描述为本项目压缩算法。完整、最近窗口和一次摘要是对照方法。
7. 拆成三个明确的手动操作：
   - “生成四份上下文”：只生成、统计和冻结工件，不调用 Agent、Tools 或最终回答评判；
   - “运行当前组合”：读取用户选中的一份冻结工件和一种 Agent，只运行 1 次；
   - “运行完整 4×3”：复用同批四份冻结工件，创建 12 个运行，每格 1 次。
8. 三种 Agent 对同一种上下文必须读取内容和哈希完全相同的冻结工件，不得分别重新摘要或压缩。
9. Session、当前事件、算法参数、Token 预算或摘要模型版本变化后旧工件不能静默复用；页面提示重新生成，不得自动开始压缩。
10. 每格只有一个样本，页面写“本次结果”或“单次样本”，不能生成平均值、稳定性结论或“必然更好”的描述。

六、精简并重做对比用例

1. 第一版目标为 20 个有效对比用例，不保留 50 多个质量不一的公开列表：
   - 4 个基础用例：无需工具、单工具、拒绝越权、信息不足；
   - 4 个组合用例：2～3 个工具，至少存在一次参数依赖或相似工具选择；
   - 6 个多工具用例：3～5 个工具，包含依赖、分支、并行查询或停止条件；
   - 3 个异常用例：空结果、超时、过期数据或来源冲突；
   - 3 个安全用例：权限、写操作确认、不可信工具返回或禁止动作。
2. 删除或合并：
   - 旧 `ctx-*` 长上下文用例；
   - 仅替换行业名但结构相同的用例；
   - 只靠工具从 6 个增加到 7 个体现难度的用例；
   - 没有参数依赖、分支和选择空间的机械长链；
   - 评判目标完全重复的用例。
3. 不要把 20 个用例机械凑数。优先复用和改好现有数据；每个保留用例必须有明确、不同的评测目标。
4. 每个多工具用例保存：固定任务、标准可见工具范围、冻结 Mock 版本、必须事实、可接受调用路径、参数依赖、可并行步骤、禁止调用、确认规则和停止条件。
5. 评判器不能只使用唯一 `expected_tools` 线性数组。增加可表达下列规则的数据结构和评判：
   - `required_calls`；
   - `required_dependencies`；
   - `acceptable_alternatives`；
   - `optional_calls`；
   - `forbidden_calls`；
   - `confirmation_required`；
   - `stop_when_facts_available`。
6. 评判配置只供调度器和评判器读取，不能进入模型输入、工具描述、匿名接口或公开用例 JSON。
7. Mock 返回必须根据参数匹配稳定数据，并能明确模拟成功、空结果、超时、权限拒绝、过期、冲突和不可信内容。同一批次固定 Mock 版本，不在重复运行之间随机变化。
8. 标准工具范围中包含目标工具、能力相近的干扰工具和少量无关工具。用户调整工具范围后将批次标记为自定义条件，不能进入正式指标。

七、实现对比用例运行

1. 用户从用例库选择一个公开对比用例，在实验模块发起运行；用例库本身负责浏览和维护，不堆叠完整运行面板。
2. 一次对比任务自动包含三种 Agent，实现方式由固定 Agent 目录读取，用户不能只挑表现更好的一个 Agent 进入正式对比。
3. 用户只选择 `repeat_count=3` 或 `repeat_count=5`。前端显示 9 或 15 个运行，后端拒绝其他数值。
4. 同一批次固定用例版本、问题、前置对话、工具定义及顺序、Mock 版本、模型、温度、Token、超时、`max_agent_steps`、权限和评判版本。
5. 三种 Agent 的执行顺序按重复编号轮换，避免总是同一种 Agent 先运行；不要因此改变输入条件。
6. 保存每一次运行，不只保存聚合值。汇总展示成功次数、最小值、中位数、最大值和离散情况；无效运行单独显示，不自动补跑。
7. 指标至少覆盖工具选择、参数和依赖、必要顺序、多余或重复调用、失败替代、权限与确认、必须事实、幻觉、Token、耗时、实际步数和停止原因。

八、匿名运行和后台任务

1. 未登录访问者可以运行公开的固定对比用例和公开压缩 Session，但不能提交任意问题、系统提示、工具定义、Mock 返回、模型地址或密钥。
2. 使用安全、不可预测、HttpOnly 的匿名身份 Cookie；任务保存匿名身份哈希。匿名用户只能查看和取消自己的任务。
3. 长任务后台执行。关闭或刷新页面不停止任务；重新进入“我的测试”可以继续查看。
4. 任务、单元进度和已完成工件必须持久化，不能只保存在进程内字典或 daemon thread。服务重启后应把未完成任务标记为可恢复、已中断或失败，不能永久显示运行中。
5. 取消只阻止尚未开始的单元；已经产生的运行和费用保留。禁止用自动补跑掩盖失败、中断或无效运行。
6. 后端执行匿名并发、每日任务数、Token、排队时长和任务最长时长限制。限制值使用服务端配置，前端只负责显示。
7. 匿名运行固定 `publishable=false`，不自动进入正式指标和公告。

九、只实现公告空框架和数据引用关系

1. 公告页自身不维护考题正文：
   - 公告中的 Agent 对比考题必须引用用例库的 `case_id + case_version`；
   - 公告中的压缩案例必须引用三个压缩 Session 的 `session_id + session_version + current_event_id`。
2. 公告展示的是经过审核的正式运行批次，不是用例定义本身。关系必须是：
   - 用例库提供考题；
   - 压缩模块提供 Session；
   - 运行系统产生答卷和证据；
   - 维护者审核并创建公开快照；
   - 公告页只读取公开快照。
3. 本任务只预留版本化“公告展示用例集”和正式发布批次的数据结构，初始内容为空。不要选择公告代表用例，不要写入实例编号，不要生成公告测试数据。
4. 本任务不设置公告正式批次的实际运行数量，不创建公告运行任务，不执行发布器，不生成公开结果快照。公告使用哪些代表用例、重复几次以及何时发布，等全部代码完成后由所有者重新确定并单独发起。
5. 公告页面只实现空框架和真实空状态，预留批次说明、Agent 对比汇总、压缩结果、代表性实例和单次运行下钻区域。没有正式发布数据时统一显示“尚未发布”。
6. 数据接口和结构要能够在以后关联运行编号、用例或 Session 版本、Agent 模式、工具目录版本、Mock 版本和评判版本，但本任务不填充这些关联数据。
7. 公告相关代码必须保留后续脱敏边界：密钥、内部路径、匿名身份、gold、预期工具路径、禁止规则和未脱敏原文不能进入公开结构。本任务不通过构造实例数据测试这条发布链路。
8. 公告页不能读取匿名临时结果、开发调试结果、手填分数或尚未运行的占位数据，也不能为了页面好看生成示例成绩。
9. 不新增公告实例或公告展示的自动化测试。等其他代码全部完成并由所有者明确要求后，再单独编写公告实验运行、实例生成和页面验收指令。

十一、前端改造

1. 实验模块一级只显示两个入口：
   - 压缩用例；
   - 对比用例。
2. 压缩用例页显示三个 Session、最新当前输入、历史范围、四种上下文、压缩前后、三个手动按钮和 4×3 矩阵。
3. 对比用例页显示普通用例、标准工具范围、可见 Mock 工具、重复 3/5、单次最大步数、总运行数、任务进度和三种 Agent 结果分布。
4. 用例库保留浏览、筛选、详情和“进入实验”入口，不在详情页重复完整实验工作台。
5. 公告页和实例展示页本轮只实现空框架、数据接口和空状态，不填充实例，不触发正式批次，也不做公告展示自动化测试。
6. 数据为空时使用真实空状态。禁止在前端脚本中硬编码成绩、运行时间、Token、调用链或成功率冒充实验结果。
7. 页面加载、开发服务器启动、静态站生成和代码构建都不能创建实验任务。
8. 保持当前网站导航、宽度、图表比例和移动端布局一致；不要为了新模块再建一套不同视觉体系。

十二、自动化测试和静态检查

允许并应执行不产生真实实验的测试。至少补充或修改：

1. `repeat_count`：对比用例只接受 3/5，压缩矩阵只接受 1；
2. `max_agent_steps`：达到上限正确停止并保存停止原因，与重复次数无关；
3. 一个对比用例准确展开成 9 或 15 个运行；
4. 一个压缩 Session 准确展开成 12 格且每格一次；
5. 只生成上下文不会创建 Agent、Tool 或评判运行；
6. 三种 Agent 复用同一上下文工件哈希；
7. 当前消息不进入历史两次；
8. 调用关系评判支持依赖、替代路径、禁止调用、确认和停止条件；
9. 匿名用户不能读取其他匿名任务，匿名结果不可发布；
10. 服务重启后的任务状态不会永远停留在运行中；
11. 非公告页面的静态站生成和页面测试不会发起实验。
