# 本地原生启动说明

本地开发不做 Docker 构建与运行(镜像构建/推送由 CI 在云端执行),全部为原生进程。
共启动 **3 个模块 + 1 个前置本机 PostgreSQL**,按顺序:PostgreSQL(等监听)→ data(等健康)→ engine(等就绪)→ web。

数据库是**本机安装的 PostgreSQL 18**(`D:\PostgreSQL\18`),不经过任何 SSH 隧道、不依赖云端实例。
密钥统一放在 `.local-services/*.bat`(与 `deploy/.env` 同源,均已 gitignore,永不提交)。

## 总览

| 模块 | 目录/位置 | 监听地址 | 就绪标志 |
|---|---|---|---|
| PostgreSQL(前置) | `D:\PostgreSQL\18` | `127.0.0.1:5432` | 5432 处于监听 |
| data(Java) | `data/` | `127.0.0.1:18081` | `/actuator/health` 返回 200(`db: UP`) |
| engine(Python) | `engine/` | `127.0.0.1:8090` | `/ready` 返回 `{"status":"ready",...}` |
| web(Node) | `web/` | `127.0.0.1:8082` | 页面可访问 |

> 端口说明:本机 `8080` 常被占用(如 Steam),data 因此固定用 `18081`;
> `LLM_BASE_URL`/`LLM_MODEL` 必须显式设置(env 是唯一真源,engine 无内置默认端点,缺失即启动/调用时报错)。

## 一键启动(推荐)

`.local-services/` 下的本机脚本(不入仓库):

| 脚本 | 作用 |
|---|---|
| `start-all.bat` | 经计划任务(touchstone-pg/data/engine/web)按序拉起四件并等就绪 |
| `run-stack-direct.bat` | 不走计划任务,直接起本机进程(最小化窗口),效果相同 |
| `stop-all.bat` | 全部停止 |

任选其一即可,无需手动分步。

## 手动分步启动

### 前置:本机 PostgreSQL

```powershell
# 等价于 .local-services/pg-start.bat
& "D:\PostgreSQL\18\pgsql\bin\pg_ctl.exe" -D "D:\PostgreSQL\18\data" -l "D:\PostgreSQL\18\logs\pg-svc.log" start
```

本机库须已执行过 `db/postgresql/setup/init.sql`(单一初始化入口)及
`db/postgresql/changes/` 下的变更脚本;进度可查 `touchstone.database_changes` 台账。

### 1. data 服务

目录 `data/`,启动命令 `mvn spring-boot:run`(等价于 `.local-services/data-start.bat`)。

启动前设置环境变量(PowerShell):

```powershell
$env:DATABASE_URL = "jdbc:postgresql://127.0.0.1:5432/touchstone"
$env:DATABASE_USER = "postgres"
$env:DATABASE_PASSWORD = "<deploy/.env 的 POSTGRES_PASSWORD>"
$env:DATA_INTERNAL_TOKEN = "<deploy/.env 的 DATA_INTERNAL_TOKEN>"
$env:SERVER_ADDRESS = "127.0.0.1"; $env:SERVER_PORT = "18081"
mvn spring-boot:run
```

数据源无默认值,缺任一变量启动直接失败(fail-fast,见 `data/README.md`)。

### 2. engine 运行 API

目录 `engine/`,使用 `engine/.venv`(缺则先 `uv sync --extra dev`)。

```powershell
$env:DATA_API_BASE_URL = "http://127.0.0.1:18081/internal/v1"   # 指向本地 data
$env:DATA_INTERNAL_TOKEN = "<deploy/.env 的 DATA_INTERNAL_TOKEN>"
$env:LLM_API_KEY = "<deploy/.env 的 LLM_API_KEY>"                # 发起批次必需
$env:ARTIFACTS_DIR = "<仓库>\engine\var\artifacts"               # 缺省 /app/artifacts 是容器路径
.venv\Scripts\python -m uvicorn bdlh_runtime.run_api:app --host 127.0.0.1 --port 8090
```

`/ready` 依赖 data,必须等 data 健康后再起。运行 API 需登录:
`POST /api/v1/login` 拿会话令牌,其余接口带 `Authorization: Bearer <token>`。
浏览器跨端口调用才需要 `RUN_API_ALLOWED_ORIGINS`;纯 API 使用不设即可(CORS 关闭)。

### 3. web 展示站

目录 `web/`,无环境变量,启动命令 `npm run dev`。

| 入口 | 地址 |
|---|---|
| 首页(代表项目门户) | http://127.0.0.1:8082 |
| 系统总览 / 实验结果 / 原始证据 / 测试逻辑 | `/overview/` `/results/` `/evidence/` `/methodology/` |

> 旧入口已退役:`/lab/`(内部运行台)与 `/docs/`(旧文档站)均 301 到对应新页;
> 发起批次走 engine 的运行 API(见上节),不再有浏览器运行台。

## 批次跑完后的发布

批次工件落 `engine/var/artifacts/`(`ARTIFACTS_DIR` 指向的目录)。投影到公开实证层:

```powershell
Set-Location web
npm run publish:showcase -- --git-commit <当前 sha>
```

发布前全量校验(有效样本门槛、逐运行哈希复算、敏感信息扫描、引用可解析),
任一条不过即拒绝发布、不部分发布。产物写 `web/public/showcase-data/`,
`git commit` 后公开页即可展示该批次。

## 排查速查

| 现象 | 先查 |
|---|---|
| data 起不来:连接失败 | 本机 PG 是否启动(5432 监听;`pg-start.bat` 或 services);`DATABASE_*` 是否设全 |
| data 健康 200 但业务 500 | 库是否执行过 init.sql;`database_changes` 台账进度 |
| engine `/ready` 503 | data 是否健康;`DATA_API_BASE_URL` 是否指向 18081 |
| 发批次报 401 | 先 `/api/v1/login`;连续失败 5 次锁 15 分钟 |
| 页面 404/旧地址 | 旧模块地址已 301 到五页新位置(映射见 `web/scripts/redirect-map.mjs`) |
| 端口被占 | `netstat -ano | findstr :<端口>`,确认是本服务残留进程再结束 |
