Skill 接入规范

面向开发者的 StockSkill 服务接入文档：服务关系、真实接口、请求响应、错误处理与安全部署。

1 · 30 秒快速理解

StockWise 的分析能力由 stock-wrapper 提供——一个独立部署的 Node.js HTTP 服务，内部调用 stock-analysis-skill 执行确定性的行情拉取、指标计算和回测。Agent 或第三方程序通过 HTTP 调用它，得到一个统一的 JSON 信封。

调用方（Agent / 程序） → POST ${STOCK_WRAPPER_URL}/api/v1/stock/analyze → stock-wrapper → stock-analysis-skill → 行情数据源 → { success, data, requestId }

最小调用链（curl）：

curl -X POST "${STOCK_WRAPPER_URL}/api/v1/stock/analyze" \
  -H "Content-Type: application/json" \
  -H "X-Internal-Token: ${STOCK_WRAPPER_TOKEN}" \
  -H "X-Request-ID: 4f9d8c2e-0001-4b1a-9c3a-abcdef000001" \
  -d '{"symbol":"600519","assetType":"stock"}'

2 · 实际服务和接口

接口地址均为占位符，实际值来自部署环境变量：${STOCK_WRAPPER_URL}、${STOCK_WRAPPER_TOKEN}。

能力方法路径
单标的分析POST/api/v1/stock/analyze
组合分析POST/api/v1/portfolio/analyze
量化分析POST/api/v1/quant/analyze
板块分析POST/api/v1/sector/analyze
存活检查GET/health
就绪检查GET/ready

3 · 请求约定

  • 所有请求 Content-Type: application/json；
  • 服务间认证使用请求头 X-Internal-Token；
  • 调用链统一传递 X-Request-ID（UUID），贯穿日志用于追踪；
  • Token 只能放在服务端环境变量或密钥管理系统，浏览器不能直接持有内部 Token；
  • 公共文档示例只使用 ${STOCK_WRAPPER_URL}、${STOCK_WRAPPER_TOKEN} 占位符。
安全：浏览器端直接调用带内部认证的 Skill 服务是被禁止的。前端只访问 StockWise 后端，由后端在服务端发起 Skill 调用。

4 · 请求与返回格式

4.1 单标的分析 POST /api/v1/stock/analyze

请求字段：

字段类型必填示例说明
symbolstring是6005196 位数字代码
assetTypestring否stockauto/stock/etf/fund/open_fund/qdii
{
  "success": true,
  "requestId": "4f9d8c2e-...",
  "command": "stock",
  "data": {
    "symbol": "600519",
    "asOf": "2026-08-02T15:00:00+08:00",
    "dataQuality": "REALTIME",
    "methodology": { "version": "1.0.0" },
    "decisionBasis": { ... },
    "sources": [ ... ],
    "profile": { ... }
  }
}

data 中行情、K 线、技术指标、评分与决策依据字段以后端返回为准；当前版本不保证字段完全稳定，接入时以实际响应为准。

4.2 组合分析 POST /api/v1/portfolio/analyze

{
  "positions": [
    {
      "code": "600519", "name": "贵州茅台", "assetType": "stock",
      "avgCost": 1400, "shares": 100, "buyDate": "2026-01-05",
      "targetWeight": 0.4
    }
  ],
  "monthlyBudget": 10000,
  "cash": 5000,
  "cashReserveRatio": 0.2
}

positions 数量 1–50，每个持仓字段校验严格（代码、名称、成本、份额、买入日期）。

4.3 量化分析 POST /api/v1/quant/analyze

{
  "codes": ["510300", "159915", "588200"],
  "benchmark": "510300"
}

codes 至少 2 个不重复的 6 位代码；benchmark 可选 6 位代码。

4.4 板块分析 POST /api/v1/sector/analyze

{
  "type": "industry",
  "limit": 20
}

type 只能是 industry 或 concept；limit 1–100。

4.5 统一成功响应 envelope

{ "success": true, "requestId": "UUID", "command": "stock", "data": { ... } }

错误响应统一为：

{ "success": false, "requestId": "UUID", "error": { "code": "INVALID_SYMBOL", "message": "..." } }

5 · 错误、超时和重试

状态含义处理
400参数校验失败（INVALID_SYMBOL / INVALID_JSON / INVALID_POSITIONS 等）修正请求，无需重试
401/403内部凭证缺失或无效（UNAUTHORIZED）检查 Token，禁止重试
404接口不存在（NOT_FOUND）检查路径
408/超时上游行情或计算超时可重试，带幂等 X-Request-ID
429触发限流（如实现）退避重试，最多 3 次
5xx服务内部错误（INTERNAL_ERROR）记录 requestId，指数退避重试，最多 3 次
重试纪律：重试必须有次数上限、退避时间，并复用幂等 X-Request-ID；禁止无限重试。Skill 执行是有副作用的行情任务，客户端不应自动无限重试。

6 · 调用示例

curl

curl -X POST "${STOCK_WRAPPER_URL}/api/v1/sector/analyze" \
  -H "Content-Type: application/json" \
  -H "X-Internal-Token: ${STOCK_WRAPPER_TOKEN}" \
  -d '{"type":"industry","limit":20}'

Node.js（服务端）

const res = await fetch(`${process.env.STOCK_WRAPPER_URL}/api/v1/stock/analyze`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Internal-Token": process.env.STOCK_WRAPPER_TOKEN,
    "X-Request-ID": crypto.randomUUID()
  },
  body: JSON.stringify({ symbol: "600519", assetType: "stock" })
});
const { success, data } = await res.json();

Java / Spring（服务端）

HttpRequest req = HttpRequest.newBuilder()
    .uri(URI.create(baseUrl + "/api/v1/quant/analyze"))
    .header("Content-Type", "application/json")
    .header("X-Internal-Token", internalToken)
    .header("X-Request-ID", UUID.randomUUID().toString())
    .POST(HttpRequest.BodyPublishers.ofString(json))
    .timeout(Duration.ofSeconds(120))
    .build();

Agent 调用最小 JSON

{ "command": "sector", "type": "industry", "limit": 20 }

7 · 安全和部署

  • Skill 服务可以独立部署（Docker / Node），通过 internalToken 鉴权；
  • Agent（Java 后端）在服务端发起调用，前端只访问 StockWise 后端，不直接访问带内部认证的 Skill；
  • Token 通过环境变量注入，日志必须脱敏，禁止打印 Token；
  • 提供 /health 与 /ready 健康检查，供编排系统探活；
  • 服务不监听公网管理端口，仅暴露业务接口与健康检查。

8 · 接入检查清单

  • 健康检查 GET /health 返回 UP
  • 就绪检查 GET /ready 返回 READY
  • 四个分析接口分别可调用
  • 缺 Token 返回 401，不泄露内部信息
  • 错误 JSON / 非法参数返回稳定错误结构
  • 超时与上游无数据时返回可读错误
  • 重试有上限且复用幂等 X-Request-ID
  • 日志不打印 Token，且 X-Request-ID 贯穿链路
  • 版本兼容：锁定 methodology.version 后升级有回滚预案
