部署与联调

前后端与 Skill 服务各自独立部署的边界、环境配置与联调步骤。

架构边界

浏览器（前端静态页） → Nginx / dev-server（静态资源 + /api 反向代理） → Java Backend（Agent、路由、SSE） → stock-wrapper（Skill 计算） / web-search-wrapper（搜索） → PostgreSQL / Redis / Ollama

独立部署原则

  • 修改前端 → 只重新部署 stockwise-frontend 静态资源；
  • 修改 Java 后端 → 才重新构建和部署后端 JAR / 容器；
  • 修改 Skill wrapper → 只部署对应 Node.js / Docker 服务；
  • 前端不保存数据库密码、内部 Token 或付费模型密钥；
  • .env.cloud.example 是模板，.env.cloud 是部署时实际配置，实际配置不得提交到 Git。

前端启动

# 开发服务器（静态资源 + API 代理到后端 8080）
cd stockwise-frontend
PORT=8083 node dev-server.js

# 验证
curl http://127.0.0.1:8083/                    # 首页
curl http://127.0.0.1:8083/docs/skill          # 文档
curl http://127.0.0.1:8083/skill-dashboard.html
curl http://127.0.0.1:8083/api-console.html

后端启动

cd stockwise-backend
mvn spring-boot:run            # 读取 application-dev.yml
curl http://127.0.0.1:8080/actuator/health

Skill wrapper 启动

cd stock-wrapper
STOCK_WRAPPER_TOKEN=xxx node src/server.js
curl ${STOCK_WRAPPER_URL}/health
curl ${STOCK_WRAPPER_URL}/ready

环境配置

变量说明
STOCKWISE_BACKEND_URL前端 dev-server 代理的后端地址，默认 http://127.0.0.1:8080
STOCK_WRAPPER_URLSkill 服务地址（后端侧配置）
STOCK_WRAPPER_TOKENSkill 内部认证 Token（仅服务端）
SPRING_PROFILES_ACTIVE后端运行 profile：dev / prod

联调步骤

  1. 启动 Skill wrapper，确认 /health、/ready；
  2. 启动 Java 后端，确认健康检查；
  3. 启动前端 dev-server；
  4. 打开 /api-console.html 测试 SSE、运行记录和 Skill 结果；
  5. 打开 /agent?name=stock 发送问题，观察路由、SSE 与运行追踪面板。
配置纪律：实际密钥只存在于本地 application-dev.yml / 部署环境变量，不得提交到 Git。仓库只跟踪 application.example.yml 模板。
