Skill 接入规范

当前平台由 BDLH Agent Runtime 统一编排领域 Skill 与外部能力：Finance Analysis Skill 负责确定性分析，Web Search Skill 负责外部搜索证据。

使用边界：Skill 由平台后端统一调用，前端和普通用户不直接访问 Skill 服务，也不需要管理 Skill 注册或服务 Token。

Finance Analysis Skill · 金融领域分析

金融领域分析由 Python Runtime 内部的 Finance Analysis Skill 执行。外部数据通过 akshare-one MCP、cn-financial MCP 或其他已注册能力获取；Skill 只负责确定性计算、数据校验和结构化总结。历史 stock-wrapper 与 Node Skill 已标记为 RETIRED，不再进入默认运行链路。

1 · 30 秒快速理解

用户请求先进入 Runtime，由 LangGraph 根据当前状态选择领域能力；模型负责理解、规划和表达，确定性计算由 Skill 完成。

调用方（Agent / 程序） → Runtime 选择 Capability → MCP Adapter 获取并标准化 Observation → Finance Analysis Skill 执行确定性计算 → { status, observations, analysis, provenance }

Skill 不提供面向浏览器的直连接口；统一入口是 Runtime 的对话和流式 API。

2 · 实际能力和入口

外部能力地址由部署环境变量配置，Runtime 负责认证、超时、降级和 Observation 标准化；前端不持有 MCP Token。

能力方法路径
统一对话入口POST/api/v1/chat/stream
金融研究能力INTERNALfinance.stock-research
组合健康能力INTERNALfinance.portfolio-health
适配性评估能力INTERNALfinance.suitability-evaluation

3 · 请求约定

  • 所有请求 Content-Type: application/json；
  • MCP 认证只能由 Runtime 服务端持有；
  • 调用链统一传递 X-Request-ID（UUID），贯穿日志用于追踪；
  • Token 只能放在服务端环境变量或密钥管理系统，浏览器不能直接持有内部 Token；
  • 前端只访问 Runtime 的统一对话与流式 API，不直连 Skill 或 MCP 服务。
安全：浏览器端直接调用带内部认证的 Skill 服务是被禁止的。前端只访问平台后端，由后端在服务端发起 Skill 调用。

4 · 请求与返回格式

4.1 能力选择 Runtime 内部

Runtime 不要求用户先把问题收敛成固定接口。它根据对话上下文和当前状态生成数据需求，再由 Capability Registry 选择可用 MCP 或 Java 数据能力。

{
  "domain": "finance",
  "capabilities": ["market-data", "financial-facts"],
  "requirements": ["latest", "historical-series"],
  "constraints": { "freshness": "session", "userScope": "current-user" }
}

4.2 Observation 标准 Runtime 内部

所有 MCP、Java 和其他外部能力返回值先转换为 Observation，再进入 Skill 或模型。Observation 必须带来源、时间、质量和降级信息，原始响应不能直接作为结论。

{
  "kind": "market.fact",
  "value": { "...": "normalized data" },
  "provenance": { "provider": "mcp", "tool": "...", "retrievedAt": "..." },
  "quality": "LIVE",
  "status": "COMPLETE"
}

4.3 Skill 结果 finance.*

Finance Analysis Skill 只消费结构化 Observation，完成指标、风险、组合或适配性计算，并返回可追溯的结构化结果。模型只负责解释和表达，不替代确定性计算。

{
  "status": "COMPLETE",
  "analysis": { "...": "deterministic result" },
  "evidence": ["observation-id-1"],
  "limitations": []
}

4.4 统一流式输出 POST /api/v1/chat/stream

前端只订阅 Runtime 的 SSE（Server-Sent Events，服务端推送事件）流，接收状态、工具调用、Observation、Skill 结果、模型文本和最终完成事件。用户无需了解内部能力的接口分类。

4.5 统一成功响应 envelope

{ "success": true, "requestId": "UUID", "status": "COMPLETE", "data": { ... } }

错误响应统一为：

{ "success": false, "requestId": "UUID", "error": { "code": "INVALID_SYMBOL", "message": "..." } }

Web Search Skill · 结构化外部搜索

Web Search Skill 通过独立的 bdlh-web-search-adapter 处理新闻、网页和舆情查询，向 Runtime 返回固定的搜索结果结构。它与 Finance Analysis Skill 分工不同：前者提供外部证据，后者负责领域内确定性计算。

方法路径用途
POST/api/search批量执行结构化搜索任务
GET/health存活检查
GET/readyProvider 就绪检查

服务端认证使用 X-Agent-ID 与 X-Search-Token。浏览器不得直接调用该服务，搜索结果需要经过 Agent 编排、来源整理和不确定性说明。

5 · 错误、超时和重试

状态含义处理
400参数校验失败（INVALID_SYMBOL / INVALID_JSON / INVALID_POSITIONS 等）修正请求，无需重试
401/403内部凭证缺失或无效（UNAUTHORIZED）检查 Token，禁止重试
404接口不存在（NOT_FOUND）检查路径
408/超时上游行情或计算超时可重试，带幂等 X-Request-ID
429触发限流（如实现）退避重试，最多 3 次
5xx服务内部错误（INTERNAL_ERROR）记录 requestId，指数退避重试，最多 3 次
重试纪律：重试必须有次数上限、退避时间，并复用幂等 X-Request-ID；禁止无限重试。Skill 执行是有副作用的行情任务，客户端不应自动无限重试。

6 · 调用示例

统一入口示例

curl -N -X POST "${BDLH_RUNTIME_ANALYSIS_URL}/api/v1/chat/stream" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <user-jwt>" \
  -H "X-Request-ID: <uuid>" \
  -d '{"message":"请分析当前问题","sessionId":"<session-id>"}'

Java、Node.js 或其他客户端都只调用统一 Runtime 入口；MCP Token、内部服务 Token 和 Skill 注册信息只能保留在服务端。

7 · 安全和部署

  • Skill 作为 Runtime 内部能力注册，外部 MCP 适配器可以独立部署；
  • Agent（Python Runtime）在服务端发起调用，前端只访问统一 Runtime，不直接访问 Skill 或 MCP；
  • Token 通过环境变量注入，日志必须脱敏，禁止打印 Token；
  • Runtime、Java 数据服务和 MCP Adapter 分别提供健康检查，供部署系统探活；
  • 内部能力不监听公网管理端口，仅暴露必要的服务间接口。

8 · 接入检查清单

  • 健康检查 GET /health 返回 UP
  • 就绪检查 GET /ready 返回 READY
  • 四个分析接口分别可调用
  • 缺 Token 返回 401，不泄露内部信息
  • 错误 JSON / 非法参数返回稳定错误结构
  • 超时与上游无数据时返回可读错误
  • 重试有上限且复用幂等 X-Request-ID
  • 日志不打印 Token，且 X-Request-ID 贯穿链路
  • 版本兼容：锁定 methodology.version 后升级有回滚预案
