压缩算法 · 上下文压缩

四种策略与符号

构建器输入为条目集合 I = {i₁,…,iₙ}(每条带分类 cls(i) ∈ {required, compressible, reference_only, distractor}、优先级 p(i)、序号 seq(i))与预算 B;输出为工作上下文消息与逐条决策(kept / compressed / referenced / omitted / isolated)。四种策略:

  • full:全量透传(预算内不压缩);
  • recent-n:只保留最近 N 条(窗口外省略);
  • single-summary:可压缩项合并为单摘要;
  • budgeted:按优先级与性价比选择压缩,仅引用项以来源元数据代表。

默认参数:N = 10,压缩目标比例 ρ = 0.35,压缩条目最小 token M = 32。

token 计数公式

计数器为保守确定性口径 conservative-cjk1-latin4-v1,版本号写入工件与处理报告。对文本 s,设:

  • C(s) = 非空白字符中属于「CJK 汉字 / 平假名 / 片假名 / 谚文 / Unicode 标点(类别 P*)」的个数;
  • L(s) = 其余非空白字符(拉丁字母、数字与其他文字)的个数;
  • 空白字符不计入。

则 T(s) = C(s) + ⌈L(s) / 4⌉。该口径刻意偏保守(高估),保证预算内绝不超出真实 tokenizer 计数。

条目渲染时附加头标:render(i, c) = [context item=ID type=cls(i) source=SID] + "\n" + c;不可信条目(trusted=false 或角色为 untrusted_data)整体包裹 <untrusted-data>…</untrusted-data>,且不进入指令区。系统提示为 bare 条目逐字透传(不加头标)。所有 token 均按渲染后文本计数。

budgeted:预算分配公式

第一步(required 全保留,红线):

R = Σ_{cls(i)=required} T(render(i, content(i)))　→　R > B 时直接判 CONTEXT_BUILD_FAILED,不静默降级;否则剩余预算 M₁ = B − R

第二步(候选排序):候选集 Cand = {i : cls(i) ∈ {compressible, reference_only}},按 (−p(i), seq(i), id(i)) 字典序升序处理(优先级高者优先,同优先级按时间先后)。跨用户条目(owner 不匹配)在此之前已被整体隔离(isolated);干扰项(distractor)不进预算,直接隔离。

第三步(逐条配额):处理到第 j 条(0 起,其后还有 m = max(1, |Cand| − j) 条)时,设当前剩余预算为 Mⱼ:

fairⱼ = max(M_min, ⌊Mⱼ / m⌋)　(均分下限保护,M_min = 32) targetⱼ = min( T_orig(j),　max(M_min, ⌊T_orig(j) × ρ⌋),　max(0, fairⱼ − T_header(j)) )

其中 T_orig(j) = T(render(iⱼ, content(iⱼ))) 为原始渲染 token,T_header(j) = T(render(iⱼ, "")) 为头标 token。三个上限分别来自「不需要压」「不许压过头」「当条配额」。reference_only 条目不走压缩,直接以一行元数据代表:[reference source=SID original_tokens=T_orig]。

第四步(入选与否):压缩产物渲染后 token ≤ Mⱼ 则入选并扣减预算(Mⱼ₊₁ = Mⱼ − T(render(iⱼ, value)));否则整条 omitted(原因记录进决策)。最终选中条目按 (seq, id) 复原时间顺序。

压缩函数 compress(i, target)

单条压缩为确定性过程,无模型调用:

  1. 规范化:按连续空行分段,段内连续空白折叠为单个空格,去掉首尾空白,并丢弃重复段落(保首次出现);
  2. JSON 紧凑化:内容以 { 或 [ 开头且可解析为 JSON 时,重写为无空白紧凑形式(键排序),否则保留规范化文本;
  3. 预算内直接返回:若 T(norm) ≤ target,原样返回(决策记 kept,不算压缩);
  4. 头尾保留:否则构造 [compressed source=SID]\n + norm[: ⌈0.6·|norm|⌉] + \n[content omitted]\n + norm[−⌈0.25·|norm|⌉:],即保头部 60%、尾部 25%,中段显式标注省略;
  5. 收缩循环:仍超预算时,对当前较大的一侧(头或尾)长度乘 0.8(下限 1 字符)重试,直至放得下;
  6. 兜底二分:极端情况下(连省略标记都放不下)在「标记 + 全文」上二分查找最大前缀长度 lo 使 T(text[:lo]) ≤ target,截断返回。

压缩后能复原的定位信息只有 source=SID 与头标——这是设计取舍:省略必须显式可辨,不允许静默截断冒充全文。

其余策略公式

  • full:全部条目按 (seq, id) 顺序渲染;Σ T(render(i)) > B 时抛 ContextWindowError(不截断冒充全量)。
  • recent-n:按 (seq, id) 排序取最后 N 条为窗口;窗口内逐条放行并扣减预算,窗口外或预算耗尽记 omitted。
  • single-summary:required 先全保留(同 budgeted 第一步);可选条目按序拼接为一个合成条目(优先级取各条最大值,来源为各条 source 逗号连接),摘要预算 = 剩余预算 − T(合成条目头标),对合成条目调用上面的 compress;放得下则全部可选条目记 compressed,否则全部记 omitted。

校验与红线

  • required 保留率 100%:决策中 action ∈ {kept, compressed, referenced} 的 required 条目集合必须等于全部 required 条目;缺失即告警并按失败口径处理;
  • 工作 token 校验:最终 W = Σ T(message.content) > B 时抛 ContextWindowError;
  • 消息拼装:可信指令类条目(system/instruction)合并为一条 system 消息,其余合并为一条 user 消息——注入条目永远进不了指令区;
  • 处理报告:记录原始/工作 token、保留/压缩/引用/隔离/省略计数、逐条决策原因与构建耗时,随九段工件落库。

接入位置:Agent 循环的模型输入拼装统一经构建器(有架构测试守卫,禁止旁路拼装)。见Agent 循环。
