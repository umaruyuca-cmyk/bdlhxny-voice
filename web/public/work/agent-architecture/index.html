动产质押 · 盯市补保

供应链金融动产质押融资:小微企业以在库货物质押获取融资,货物价格下跌会使在押货值缩水、触发补保。系统每日汇总 SKU 市价与在押货值,跌破阈值自动生成补保工单,并生成风险报告辅助风控处置。本页为脱敏版:隐去行方服务编码、内部接口路径与实现细节,保留业务流程与设计决策。

金额与业务状态由 Java 确定性计算;Agent 只做只读取数与报告生成,不参与审批与资金操作。

入库 / 提货 / 盘点 / 解押仓储质押四类动作
5% 阈值跌破即生成波动工单
待补金额纳入还款试算与资金拆分
只读Agent 不碰写接口
01

业务处理全流程

质押入库 → 盯市预警 → 补保处置 → 解押
质押入库与库存占用Java货物入库登记,建立质押关系与库存占用,作为后续盯市与货值计算的基准。
每日盯市取价Java汇总各 SKU 市价与在押数量,计算在押货值;取价结果留快照,保证事后可复核。
阈值判定与待补金额Java跌幅触发阈值(如 5%)即判定需补保,按质押敞口计算待补金额。
生成补保工单Java工单含标的、跌幅、在押货值与待补金额;同一标的同业务日不重复开单。
异步生成风险报告Agent工单落库后异步唤起 Agent:只读取数 + RAG 检索历史处置案例,输出结构化风险报告。
人工审批人工风控审批通过或作废历史工单;Agent 不参与决策,只提供报告依据。
补保与资金处理Java待补金额纳入还款试算与资金拆分,进入资金链路闭环。
解押或处置Java补足后解押提货;未补足则走质押物处置流程。
02

系统职责划分

Java 业务系统为主体 · Agent 为其中一个能力模块

前端 · 风控工作台

报告卡片 / 工单列表渲染结构化报告;聊天追问页以 SSE 流式对话承接风控人员的连续追问。

↕ SSE 流式

Agent 服务 · Python 独立进程

create_agent / 自研循环统一编排:工具分支负责取数,上下文分支负责组装;经查询接口读取 Java 侧业务数据,不直接写库。

↕ MQ / HTTP 异步调用(工单生成后触发)

后端 · Java 业务系统

工单、持仓、市价汇总由 Java 直管;金额与状态为确定性计算,审批与资金拆分不经过 Agent。

并发形态:Java 多实例 × Python 单进程异步。Agent 服务由工单事件异步唤起,不参与业务主链路的强一致事务,避免模型耗时影响核心资金链路。

03

关键设计决策

为什么这么切分

金额由 Java 确定性计算

  • 在押货值、待补金额全部在 Java 侧算出
  • Agent 只读展示与解释,不重算、不裁决
  • 避免模型算术误差进入资金链路

Agent 只读边界

  • 仅开放查询接口,无写权限
  • 审批与资金操作不经过 Agent
  • 权限由代码强制,不依赖模型自觉

异步解耦,不进主事务

  • 工单落库后再发消息唤起 Agent
  • 模型耗时不拖长业务事务
  • Agent 超时或失败不影响工单流转

幂等防重

  • 同一标的同业务日不重复生成工单
  • Agent 侧消费幂等,不重复出报告
  • 重复消息与重试不产生重复副作用

取价快照可复算

  • 每次盯市取价留痕
  • 报告事后可按当时快照复核
  • 价格波动不会让历史结论对不上账

失败可降级

  • Agent 不可用时工单仍走人工审批
  • 报告缺失不影响补保与资金闭环
  • 能力是增强项,不是关键路径依赖
04

Agent 模块 · 工具与取数

三类只读工具,取数路径经适配器收敛

波动查询

  • rest api adapter → Java 盯市接口
  • 返回跌幅 / 货值 / 待补金额
  • 金额口径由 Java 侧确定,Agent 不重算

SKU 趋势

  • 外部行情接口取价格序列
  • 用于趋势描述与区间判断
  • 外部数据带时效标记,过期即降权

RAG 检索

  • 向量库:品类政策 / 历史处置案例
  • 为结论提供可追溯依据
  • 检索结果作为引用证据进入报告

结构化输出

  • Pydantic 约束输出结构
  • 报告字段与前端卡片一一对应
  • 无法证实的部分显式留空,不编造
05

Agent 模块 · 上下文管理

单 session · 自动压缩 · 归档 · 长期记忆

单 session 与事件注入

  • 风控从通知点进入,按工单建立追问会话
  • 会话初始化注入该工单的事件摘要
  • 避免风控人员重复描述背景

自动压缩

  • 会话历史只带最近 N 轮原文
  • 更早轮次压缩为摘要归档
  • 在有限上下文内保留追问连续性

归档与再检索

  • 历史报告 / 历史会话落归档
  • 可再经 RAG 检索取回
  • 支撑跨工单的同类风险对照

长期记忆

  • 客户风险偏好等稳定画像
  • 在后续报告中复用
  • 只沉淀已确认信息,不由推断直接写入

与本站 Agent 工程问题的对应

本项目中的做法对应的 Agent 工程问题
只读工具:Agent 经查询接口读数据,不碰写→治理层:权限与只读边界由代码强制执行,模型不可越权
金额由 Java 确定性计算,Agent 只做解释与归纳→模型提议、代码裁决:确定性计算不下放给模型
结构化输出 + 取价快照:报告可追溯、可复算→评测的可复算:结果必须能回溯、能重验
工单幂等 + 消费去重:重复消息不产生重复副作用→Agent 任务的唤醒去重与重复执行防护
