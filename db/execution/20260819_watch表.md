## 表结构要点

| 表 | 关键列 | 约束 |
|---|---|---|
| `runtime.watch_rule` | id(BIGSERIAL PK), user_id, type, config(JSONB), status, last_fired_at, created_at, updated_at | type CHECK ∈ {price_threshold, daily_briefing, post_market_review}；status CHECK ∈ {active, paused} |
| `runtime.watch_event` | id(BIGSERIAL PK), rule_id, type, source, payload(JSONB), dedupe_key, occurred_at, created_at | **dedupe_key UNIQUE**（幂等物理承载）；source CHECK ∈ {market_poll, cron, demo_inject}；type 同上 |

设计取舍：
- `watch_event.rule_id` **不加外键约束**——规则可删除而事件留作审计（设计文档 §4.8 事件流水语义）。
- `user_id` 用 `VARCHAR(128)` 与 runtime schema 其它表（financial_task / user_notification）一致；演示用户 ID=1 以字符串 `'1'` 存储。

## 验收要点

- `\d runtime.watch_rule` 与 `\d runtime.watch_event` 表结构与列注释完整。
- 重复插入相同 `dedupe_key` 报唯一冲突：
  ```sql
  INSERT INTO runtime.watch_event(rule_id,type,source,payload,dedupe_key)
    VALUES (1,'price_threshold','demo_inject','{}','dup-test');
  INSERT INTO runtime.watch_event(rule_id,type,source,payload,dedupe_key)
    VALUES (1,'price_threshold','demo_inject','{}','dup-test');  -- 应报 unique constraint violation
  ```
- `INSERT` 非法 `type` / `source` 值被 CHECK 拦截。
- 演示 seed 不受影响（watch 表无 seed 数据；规则由 WO-T1-7 演示注入端点或运行时接口创建）。
- `cd sentinel-engine && uv run python -m pytest -q` 全绿（WO-T1-2 起补 watch 包测试）。
